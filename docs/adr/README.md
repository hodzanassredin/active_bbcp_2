# Записи решений

Каталог хранит записи архитектурных решений этой ветки: что нужно было решить, что выбрано, какие
варианты рассматривались и почему отвергнуты. Остальная документация описывает систему такой, какая
она есть, и не рассказывает, как к ней пришли. Здесь, и только здесь, уместна история: прошедшее
время, отвергнутые варианты, хеши коммитов, номера заданий.

Запись нужна тому, кто собирается изменить устройство и хочет знать, не пробовали ли его вариант и
чем он кончился. Если вариант уже отвергнут с числом замера или фактом кода, новая попытка должна
объяснить, что изменилось с тех пор.

## Как добавить запись

1. Файл — `docs/adr/NNNN-короткое-имя.md`; номер — следующий свободный, по времени принятия решения.
2. Форма: заголовок; строка статуса и даты; разделы «Задача», «Решение», «Рассмотренные варианты»,
   «Следствия», «Не установлено» (если есть), «Источники». Правила — скилл
   `.claude/skills/bb-docs/SKILL.md`, жанр «Запись решения».
3. Вариант и причину отказа записывают, только если они найдены в источнике или прямо следуют из кода
   или замера. Чего нет в источниках, идёт одной строкой в «Не установлено».
4. Принятую запись не переписывают. Если решение пересмотрено, заводят новую запись, а у старой меняют
   только статус: «заменено записью NNNN».
5. Строку новой записи вносят в таблицу ниже.

Статусы: «принято», «принято, в работе», «заменено записью NNNN», «отвергнуто».
