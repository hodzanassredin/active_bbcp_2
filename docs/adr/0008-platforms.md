# 0008. Платформы: Linux x64 первой, затем Windows x64 и i386

Статус: принято. Дата: 23.11.2026; i386 включён в расширение 24.11.2026.

## Задача

Ядро, переключатель стеков, сторожевая страница и генератор кода зависят от архитектуры и ОС. В
репозитории два файла ядра (`System/Mod/Kernel.cp` для i386 и `System/Mod64/Kernel.cp` для amd64),
два генератора (`CPC486`, `CPCamd64`) и платформенные модули Linux и Windows. Нужно было решить, где
расширение работает и в каком порядке, при одном исполнителе и без машины с Windows.

## Решение

Первая цель — Linux x64, вторая — Windows x64 (проверка под wine), i386 получил ядро задач и
`Tasks`. Машинная часть задач — `Taskarch`, по файлу на платформу (запись 0014).
Состояние платформ — `docs/implementation.md`, раздел 10; команды — `docs/building.md`, раздел 6.

## Рассмотренные варианты

**32-битная цель без новых возможностей.** План так и предлагал: «32-битные ядро и генератор
продолжают собираться, но новых возможностей не получают, пока вы не скажете иначе»; для x86 —
«позже, по решению». Следующим заданием i386 сделан: ядро задач, переключатель x86 в `Taskarch`,
`Tasks`. Самосборка — 98 файлов без различий.

**Windows через волокна ОС, как у Темпла.** План держал вопрос «фиберы против собственного
переключателя» открытым. Взят свой переключатель `[code]` и `VirtualAlloc` со сторожевой страницей
`PAGE_NOACCESS`: один механизм на все платформы.

**32-битный тест сопрограмм без C-тулчейна.** Хелпер `libtest64.so` на i386 без 32-битного crt не
собирался. Принят свой 32-битный C-тулчейн без sudo (`tools/i386-toolchain.sh`), а не установка
пакетов: в задании действовал запрет `sudo` и `apt`.

**Слить два файла ядра в один.** Любая правка вносится дважды. Отложено: это решение автора
64-битного ядра (`docs/kernel-plan.md`, 5.4; запись 0016).

## Следствия

- Каждая правка ядра вносится в оба `Kernel.cp` одинаково и проверяется тремя прогонами:
  `tools/test.sh`, `tools/test32.sh`, `tools/test-win64.sh`.
- Мир i386 строится загрузочным `dev0Linux` и базой в `.work/i386`.
- Долг: нет GUI-проверки под Windows; индекс кластеров есть только в `Mod64`.
