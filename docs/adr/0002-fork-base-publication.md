# 0002. Основа форка, публикация, лицензия и рабочие копии

Статус: принято. Дата: 23.11.2026 (основа), 24.11.2026 (публикация, лицензия, рабочие копии).

## Задача

Работа началась как форк `bbcb/bbcp` от ветки `blackbox20`: ветка `active` несла стенд, тесты и первые
правки ядра в `.odc`. 23.11.2026 Иван Денисов прислал новую версию кода снимком, не через git:
исходники в UTF-8 `.cp`, документация в `.md`, GTK4, своя сборка `dev0Linux`. Нужно было решить, на
чём строить дальше, где хранить работу, под какой лицензией её отдавать и как вести две задачи
одновременно, если сборка пишет временные файлы хоста в общий `/tmp`.

## Решение

Снимок Ивана лёг коммитом f03eaab7 в ветку `ivan-dia261123` поверх `b3e3b9d0` из `blackbox20`, без
каталогов `OLD/`, `build/` и объектных файлов. Ветка `active2` идёт от этого снимка; ветка `active`
осталась как есть. Работа ведётся в публичном репозитории на GitHub, лицензия — BSD 2-Clause, как у
`bbcb/bbcp`. Рабочий журнал `docs/current-tasks.md` в git не входит. Две рабочие копии делает
`tools/worktree.sh`, а `tools/iso.sh` даёт команде свой `/tmp` (`docs/building.md`, раздел 8).

## Рассмотренные варианты

**Продолжать ветку `active` на `blackbox20`.** История в git, без переноса. Отвергнут: снимок
Ивана перешёл на текстовые `.cp`, а 41 модуль изменён по смыслу и 121 новый. Сравнение показало, что
`System/Mod64/Kernel` по смыслу совпал с базой, и наши правки ядра легли на снимок без конфликтов.
Работать в `.odc` дальше значило бы расходиться с автором 64-битного ядра.

**Локальный форк без публикации.** План до ответа владельца исходил из локального форка и спрашивал,
нужен ли публичный репозиторий сразу. Принята публикация: с заданий s21–s23 репозиторий называется
публичным, отсюда запрет локальных путей в файлах и вынос журнала из git (коммит a7bc6125).

**Общий `/tmp` для параллельных копий.** Проще. Отвергнут по факту сбоя: хост `dev0Linux` пишет
текст исходника в `/tmp/odcNNNNN`, сценарии перед запуском чистят такие файлы, и вторая сборка
стирает файлы первой. Компилятор получает пустой текст, в журнале — `MODULE expected`. Тот же
механизм ронял первый `build64.sh --clean`: имена из `clock()`, не больше 200 попыток. `LinFiles`
исправлен по существу (уникальные имена, удаление при закрытии), но `dev0Linux` — старый бинарник,
поэтому отдельный `/tmp` нужен.

## Следствия

- Каждая правка — отдельный коммит, пригодный для предложения в исходный репозиторий.
- Возврат к ядру без расширения описан списком файлов (`docs/building.md`, раздел 9).
- Новая копия не имеет собранного компилятора: первой идёт самосборка, иначе загрузочный компилятор
  не знает `[exclusive]`.
- Долг: `RobustParallel` проверен только по опубликованному интерфейсу, кода Ивана нет в открытом
  доступе.

## Не установлено

- Чем выбрана именно BSD 2-Clause, кроме совпадения с `bbcb/bbcp`, в источниках нет.
