# 0014. Один модуль `Tasks` и машинная часть `Taskarch` на платформу

Статус: принято. Дата: 24.11.2026.

## Задача

После переноса задач на i386 было два файла `Tasks`: `System/Mod/Tasks.cp` и `System/Mod64/Tasks.cp`,
по 690 строк, различавшихся 97 строками диффа — переключателем и раскладкой кадра. Ревью назвало это
дублированием: любая правка планировщика вносилась дважды. Ограничение: переключатель — процедура
`[code]`, её байты разные для x86 и amd64, а `DevLibrarian` выбирает файл модуля по каталогу `Mod`
или `Mod64`.

## Решение

`Tasks` — один файл `System/Mod/Tasks.cp` для обеих платформ. Всё машинное вынесено в модуль
`Taskarch`, по файлу на платформу (`System/Mod/Taskarch.cp`, `System/Mod64/Taskarch.cp`): размер
слова `word`, раскладка начального кадра (`entryOff`, `stackHead`) и сам переключатель `Switch`.
`Tasks` берёт из `Taskarch` только эти имена. Устройство — `docs/implementation.md`, разделы 1 и 2.

## Рассмотренные варианты

**Два файла `Tasks`.** Каждая платформа видна целиком в своём файле. Отвергнуто: правки планировщика,
кучи спящих, пула и отмены вносились бы дважды (ревью, «Принципы BlackBox»).

**Имя из двух слов, например `TasksArch`.** По правилу BlackBox первое слово имени модуля — подсистема
(`StdLibrarian.SplitName` режет имя перед первой заглавной после строчной). `TasksArch` попал бы в
несуществующую подсистему `Tasks`, файл `Tasks/Mod/Arch.cp`. Одно слово `Taskarch` держит модуль в
подсистеме `System` рядом с `Tasks`, и сборка находит его по `System/Mod` и `System/Mod64`. Причина
следует из кода `SplitName`; отдельного обсуждения в источниках нет.

## Следствия

- Планировщик правится в одном месте; i386 и amd64 различаются только `Taskarch`.
- `Switch` — `[code]`: компилятор вставляет его байты в место вызова, межмодульного вызова нет.
- Вместе с выносом добавлен тест трапа у дна стека задачи (коммит a740f47e).
- Долг: ядро по-прежнему два файла (`docs/kernel-plan.md`, 5.4).

## Не установлено

- Рассматривались ли платформенные вставки внутри одного файла `Tasks` — в источниках нет.
