# 0010. Тесты в подсистемах `<Sub>_dev`; тест не требует правок ядра

Статус: принято. Дата: 24.11.2026 (подсистема `Unit` — 23.11.2026).

## Задача

Тестов компилятора и сборщика в исходном репозитории не было: модули `Check` запускались вручную.
Подсистема `Unit` (`UnitAssert`, `UnitRunner`) дала прогон без окон с кодом завершения. Оставалось
решить, где лежат тесты, как их называть и что им позволено. Ограничения: правило BlackBox
«подсистема — первое слово имени модуля» (`StdLibrarian.SplitName` отрезает подсистему перед первой
заглавной буквой после строчной); поставочная сборка тестов не включает; файлы Ивана не меняются.

## Решение

Тесты подсистемы `Sub` лежат в отдельной подсистеме `Sub_dev` рядом с ней: файл
`Sub_dev/Mod[64]/<Тема>.cp`, модуль `Sub_dev<Тема>`. `UnitRunner.Run System` находит загруженные
`System_dev*`, `Run all` — все `_dev`. Правило: тест пользуется только тем, чем пользуется обычный
модуль; внутренние инварианты ядро проверяет само через `ASSERT`, а не экспортирует проверяльщика.
Соглашение — `Unit/Docu/ru/Testing.md`, разделы 4 и 5.

## Рассмотренные варианты

**Общая подсистема `Test64`.** Так тесты жили с первого стенда. Расформирована заданием s20:
тесты переехали к тем подсистемам, которые проверяют.

**Тесты внутри проверяемой подсистемы** (`<Sub>/Mod/Tests<Тема>.cp`, модуль `<Sub>Tests<Тема>`).
Принято в s20 и через одно задание отменено владельцем: ради соглашения пришлось править
инструменты — `CompileSubs` пропускал `Tests*.cp`, ключ `^` разрешался модулям с подстрокой `Tests`,
`bootstrap.sh` временно убирал тесты из `Dev/Mod`. Это подгонка инструментов под соглашение.
Правки компилятора откачены (коммит 44ba4200).

**Подсистема `<Sub>Tests` или `<Sub>tests`.** По `SplitName` имя `SystemTests…` попадает в
подсистему `System`. Поэтому выбрано строчное продолжение после подчёркивания: `System_tests`.
Шаг 0 задания s21 проверил, что подчёркивание в имени модуля и каталога принимают компилятор,
загрузчик, линкер, `Meta` и сценарии на трёх целях; запасное имя без подчёркивания не понадобилось.

**Суффикс `_tests`.** Заменён на `_dev` владельцем (задание s22): это принятая в сообществе практика
(`Comm_dev` рядом с `Comm`), и в `_dev` лежат не только тесты — замеры, пробные модули, файлы,
которые компилятор обязан отвергнуть.

**Диагностические экспорты ядра для тестов.** `ClusterIndexCheck`, `UnregisterStackAt`,
`CurrentStack`, `InRegisteredStack`, `GetTrapViewer` существовали ради тестов или обходов. Убраны:
тест `InHeap` переписан чёрным ящиком через `Kernel.Allocated`, инвариант индекса — `ASSERT` при
`debug`. `GetTrapViewer` был обходом дефекта: в 64-битной консоли трап внутри `Kernel.Try` без
зрителя трапов завершал процесс. Дефект исправлен (`HandleTrap` фатален только при `tryCount = 0`),
обходы в `UnitRunner`, `DemoGroup` и других убраны. Экспортов ядра 80 → 75 (amd64), 77 → 73 (i386).

## Следствия

- Поставочные сборки подсистем `*_dev` не включают; тесты собирают `tools/unit.sh`, `tools/go64.sh`,
  `tools/test32.sh`, `tools/test-win64.sh`.
- `git diff f03eaab7 -- Dev/Mod` не содержит ничего, связанного с тестами.
- Модули `Check*` Ивана остались на месте и не переведены на `Unit`.
- Счётчики тестов при каждом переносе совпали до и после: 107 тестов x64, 44 i386, 13 под wine.

## Не установлено

- Чем владельцу не подошла общая подсистема `Test64` — задание s20 причину не называет.
