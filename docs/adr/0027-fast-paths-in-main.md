# 0027. Быстрые пути ядра и мониторов в основной ветке, без смены стеков

Статус: принято. Дата: 25.11.2026.

## Задача

В экспериментальной ветке `active2-fast` накопились ускорения задач и мониторов: быстрый путь
свободного монитора, правило запуска сборки по росту кучи, прямое переключение задача → задача,
токен текущей задачи, скрытое поле владельца объекта, короткий ответ `IsLocked`, перенос переключателя
в `Taskarch.Switch`. Часть работы меняла способ выделения стеков: проверка границы в прологе, плиты,
поставщики `StackDir`, плотные стеки, один `Kernel.Try` на проход планировщика, трап на
альтернативном стеке. Владелец решил перенести в основную ветку только то, что не меняет стеки и не
является большой переделкой ядра; основная ветка остаётся на стеках в виртуальной памяти со
сторожевой страницей.

## Решение

В основную ветку перенесены коммиты `3b313fab`–`240da1b6` без смены выделения стеков: быстрый путь
`hot` в `Monitors`; `gcGoal` в `Kernel.NewBlock`; прямое переключение `Tasks.Leave` с `directMax = 64`;
поле `token` крючка, заменённое затем переменной `Kernel.monTok`; скрытое поле `@mon` и вставка
компилятора (`FastLockEntry`, `FastUnlockExit`, `Kernel.LockAt`); `IsLocked` без поиска; первый запуск
задачи через `Step`; встроенное переключение в `Leave`; `jmp` вместо `ret` в `Taskarch.Switch`.
Устройство описано в `docs/implementation.md`, числа — в `docs/measurements.md`, замеры стеков — в
`docs/stacks-study.md`.

## Рассмотренные варианты

**Проверка границы стека в прологе по ключу `%`.** Прототип не собрался: обращение к переменной ядра
из скрытой области `"$$"` в модуле без исключающих процедур давало адрес входа в область данных.
Причина не найдена, цена проверки не измерена; не перенесено.

**Плиты стеков и плотные стеки.** Проба плит убирала 75 % цены первого создания, но переполнение одной
задачи портит соседний стек, а без проверки в прологе безопасного варианта нет. Поставщики `StackDir`
и плотные плиты с канарейкой — отдельная переделка выделения стеков; не перенесено.

**Один `Kernel.Try` на проход планировщика и трап на альтернативном стеке.** Меняют контекст `Try` и
обработку трапа, то есть ядро, а не горячий путь задачи; не перенесено.

**Оставить ускорения в отдельной ветке.** Отвергнуто владельцем: перенос не меняет язык программы и
раскладку стека, кроме одного слова у типа с исключающими методами, и не требует второй сборки мира.

## Следствия

- Запись 0015 «Две ветки» заменена: быстрый путь монитора и правило сборки теперь в основной ветке.
- Пара «вход — выход» свободного монитора — несколько инструкций в исключающей процедуре; у типа с
  исключающими методами появляется скрытое поле `@mon`, у типа меняется отпечаток, импортирующие
  модули перекомпилируются.
- Задача в точке ожидания переходит прямо к голове очереди готовых, до 64 раз подряд; первый запуск
  задачи по-прежнему идёт через `Step`.
- Стеки задач не изменились: виртуальная память, сторожевая страница, `mmap`/`mprotect`/`munmap`.
- `Kernel.Scheduler` больше не имеет метода `current`: токен лежит в `Kernel.monTok`, его пишет
  `Tasks.SetCurrent`.

## Не установлено

- Цена проверки границы стека в прологе не измерена: прототип не собрался.
- Поведение стека без сторожевой страницы на переполнении не проверялось: вариант не внесён.
