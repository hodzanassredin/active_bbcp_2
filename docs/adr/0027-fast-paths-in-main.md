# 0027. Быстрые пути ядра в основной ветке, без смены стеков

Статус: принято. Дата: 25.11.2026.

## Задача

В экспериментальной ветке `active2-fast` накопились ускорения задач: правило запуска сборки по
росту кучи, прямое переключение задача → задача, перенос переключателя в `Taskarch.Switch`.
Часть работы меняла способ выделения стеков: проверка границы в прологе, плиты, поставщики
`StackDir`, плотные стеки, один `Kernel.Try` на проход планировщика, трап на альтернативном
стеке. Владелец решил перенести в основную ветку только то, что не меняет стеки и не является
большой переделкой ядра; основная ветка остаётся на стеках в виртуальной памяти со сторожевой
страницей.

## Решение

В основную ветку перенесены без смены выделения стеков: `gcGoal` в `Kernel.NewBlock`; прямое
переключение `Tasks.Leave` с `directMax = 64`; первый запуск задачи через `Step`; встроенное
переключение в `Leave`; `jmp` вместо `ret` в `Taskarch.Switch`. Устройство описано в
`docs/implementation.md`, числа — в `docs/measurements.md`, замеры стеков — в
`docs/stacks-study.md`.

## Рассмотренные варианты

**Проверка границы стека в прологе.** Прототип не собрался: обращение к переменной ядра из скрытой
области `"$$"` в модуле без специальных процедур давало адрес входа в область данных. Причина не
найдена, цена проверки не измерена; не перенесено.

**Плиты стеков и плотные стеки.** Проба плит убирала 75 % цены первого создания, но переполнение
одной задачи портит соседний стек, а без проверки в прологе безопасного варианта нет. Поставщики
`StackDir` и плотные плиты с канарейкой — отдельная переделка выделения стеков; не перенесено.

**Один `Kernel.Try` на проход планировщика и трап на альтернативном стеке.** Меняют контекст
`Try` и обработку трапа, то есть ядро, а не горячий путь задачи; не перенесено.

**Оставить ускорения в отдельной ветке.** Отвергнуто владельцем: перенос не меняет язык программы
и раскладку стека, и не требует второй сборки мира.

## Следствия

- Задача в точке ожидания переходит прямо к голове очереди готовых, до 64 раз подряд; первый
  запуск задачи по-прежнему идёт через `Step`.
- Стеки задач не изменились: виртуальная память, сторожевая страница, `mmap`/`mprotect`/`munmap`.

## Не установлено

- Цена проверки границы стека в прологе не измерена: прототип не собрался.
- Поведение стека без сторожевой страницы на переполнении не проверялось: вариант не внесён.
