# 0006. Точки уступки по ключу компилятора `^` вместо вытеснения

Статус: принято. Дата: 23.11.2026.

## Задача

Кооперативная задача отдаёт процессор только в точках переключения. Счётный цикл без вызовов
ожидания замораживает остальные задачи и главный цикл: окна не перерисовываются, сроки не
наступают. Нужен способ прерывать такой цикл. Ограничения: вытеснения сигналом нет (запись 0001);
каркас нельзя переключать посреди его операции — участник обсуждения (Adimetrius) спросил о
переключении «посреди `WriteChar`».

## Решение

Ключ модуля `^` (`CompileThis Модуль^`) велит компилятору вставить вызов `Kernel.Poll` в конец тела
каждого цикла `WHILE`, `REPEAT`, `LOOP` и `FOR` — на обратный переход, в дереве `CPP`, один раз для
обеих архитектур. `Tasks.Step` поднимает флаг раз в 5 мс; `Poll` уступает, только если флаг поднят,
код исполняется в задаче и задача не держит монитор. Модули каркаса (явный список: модули `System` и
подсистемы `Std`, `Text`, `Form`, `Host`, `Dev`, `Lin`, `Win`) с ключом не компилируются. По умолчанию
ключ выключен. Правила — `Docu/ru/Active-CP-Lang.md`, разделы 7 и 9.2.

## Рассмотренные варианты

**Вытеснение сигналом таймера.** Не требует перекомпиляции. Отвергнуто и не планируется: нужны точные
карты стека и правки всего каркаса (план 6.2, обсуждение в чате, раздел 4).

**Ключ по умолчанию включён.** С ним задача уступает на любом витке, и общие данные нужно защищать
всегда, даже между двумя соседними операторами. Принят выключенный ключ, включаемый помодульно.

**Уступка внутри монитора.** Отвергнута: `Poll` не уступает, пока задача держит монитор. Внутри
исключающей процедуры переключиться можно только явным `ACTIVE.AWAIT`, поэтому монитор остаётся
границей целостной правки и для точек ключа.

**Каркас определять по первому слову имени.** Первая версия считала каркасом любой модуль с
однословным именем, и пользовательский `Usermod^` отвергался. Ревью отметило, что список подсистем
зашит в компилятор, а однословное имя — не признак каркаса. Принят явный список (коммит fa3bb6f9).

**Вызов процедуры на каждом витке против проверки переменной в коде.** План выбрал вызов как первую
версию и оставил замену на проверку переменной, если замер покажет заметную цену. Принят вызов.

**Ключ только для amd64.** На шаге работ s6 32-битная цель ключ отвергала. После переноса ядра
расширения на i386 ключ разрешён и там (коммит 65f7f0e2).

## Следствия

- Счётный цикл, скомпилированный с `^`, не замораживает главный цикл (тест `Dev_devYield`).
- Отмена задачи срабатывает и в точке уступки.
- Точки уступки — будущие безопасные точки для остановки нитей сборщиком (план, «Задел»).
- Модуль без ключа получает тот же объектный код, что в Component Pascal.
- Символ `^` выбран исполнителем без владельца (отчёт s6, «Решения без владельца»).

## Не установлено

- Мерили ли цену вызова `Poll` на виток против проверки переменной — замера в источниках нет.
