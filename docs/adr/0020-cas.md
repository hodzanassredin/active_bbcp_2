# 0020. Хранилище по содержимому Cas на чистом Component Pascal

Статус: принято. Дата: 24.11.2026.

## Задача

Нужно неизменяемое хранилище блоков, названных своим хешем: основа для снимков акторов (запись 0018)
и для наборов изменений. Требования задания: хеш SHA-256 с проверкой по векторам NIST; абстрактное
хранилище по образцу `Files.Directory` с реализациями в памяти и в каталоге; нарезка длинного потока
по содержимому; дерево Меркла для большого объекта; наборы изменений с публикацией через «сравнить и
заменить» и явным переносом без слияния содержимого. Ограничения: одна нить, синхронные файлы, сборка
для amd64 и i386 из общего `Mod`, без внешних библиотек и без установки пакетов.

## Решение

Подсистема `Cas` из шести модулей в `Cas/Mod`: `CasHash`, `CasStore` (абстракция и реализация в
памяти), `CasFiles`, `CasChunk`, `CasTree`, `CasChange`. Устройство — `Cas/Docu/ru/Cas.md`.

## Рассмотренные варианты

**Готовая библиотека на C или LMDB.** Отвергнута условием задания: внешняя зависимость требует
установки пакета на каждой машине и интерфейсного модуля под каждую платформу, а установка пакетов
на стенде запрещена.

**Отдельный модуль `CasMem`.** Задание называло его отдельно. Реализация в памяти заняла около 60
строк и нужна каждому тесту и примеру; она помещена в `CasStore` рядом с абстракцией, как `Files.dir`
рядом с `Files.Directory`. Модулей стало шесть вместо семи.

**Нарезка ровно по размеру против нарезки по содержимому.** Пример `ObxCas1`: два входа по 300 000
байт, во втором десять байт вставлены в середину. По 8192 байта общих кусков 18 из 37, по содержимому
— 30 из 31. Нарезка по размеру отвергнута.

**Rabin против Buzhash.** Выбран Buzhash: скользящий хеш — поворот на бит и два исключающих «или» по
таблице, без умножения и деления по модулю многочлена. Нарезка идёт со скоростью 570–640 МБ/с на
amd64 (`docs/measurements.md`, раздел 12), в двадцать раз быстрее SHA-256, поэтому скорость записи
определяет хеш, а не нарезка. Отпечатки Рабина не реализовывались и не замерялись.

**Таблица Buzhash: 256 констант в тексте против генератора.** Задание просило таблицу, заданную в
коде. Таблица строится в теле `CasChunk` генератором xorshift32 с постоянным зерном: пять строк вместо
64 строк констант. Постоянство закреплено тестом `Cas_devChunk.TestMatchesReference`: точки разреза
сверяются с эталоном на Python, и на i386 они те же.

**SHA-256 в `LONGINT` против `SYSTEM.ROT` и сложения `INTEGER`.** Первый вариант складывал слова в
`LONGINT` по модулю 2^32 и поворачивал делением: 5,2 МБ/с (3103 мс на 16 МБ, один прогон). Второй
опирается на то, что сложение `INTEGER` в BlackBox отбрасывает перенос, а `SYSTEM.ROT` для `INTEGER`
оба генератора кода (`DevCPC486`, `DevCPCamd64`) переводят в машинный ROL/ROR 32-битного слова:
24–31 МБ/с. Векторы NIST проходят на amd64 и i386; выбран второй (коммит f12f2cdd).

**Пустой блок.** `NEW` открытого массива длины 0 трапует 134 (`NEW(b, 0)` с константой — ошибка
компиляции). Пустой блок запрещён предусловием `Put` (трап 20); пустой поток `CasTree` хранит узлом
без детей.

**Атомарная запись файла средствами `Files.Register`.** `LinFiles.Register` для малого файла без
файла подкачки создаёт файл сразу под постоянным именем и пишет в него буфер, то есть недописанный
файл виден. `CasFiles` пишет под именем `tmp-write` и переименовывает `Files.dir.Rename`
(`rename(2)`).

## Следствия

- Блоки неизменяемы и проверяются при чтении; ошибка среды — `res`, не трап.
- `CasRef` неделим только внутри процесса; хранилищем в каталоге пользуется один процесс.
- `CasRef` сначала возвращал только BOOLEAN, и ошибку записи вызывающий узнавал по `res` следующего
  `GetRef`; по замечанию координатора добавлен `OUT res`: `FALSE` при `res = ok` — ровно несовпадение.
- Хранилище только растёт: сборки мусора по блокам нет.
- `Rebase` читает чужую цепочку до родителя набора при каждом вызове.

## Не установлено

- Сравнение SHA-256 с более быстрыми хешами (BLAKE3, xxHash) — не реализовывались и не замерялись.
- Скорость SHA-256 и нарезки на i386 — замер не проводился, проверена только правильность.
- Поведение `CasFiles` на Windows (замена имени при `Rename`) — не проверялось.
