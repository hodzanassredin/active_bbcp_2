# Обзор на примерах: ObxTasks0

Две задачи увеличивают общий счётчик без монитора.

Две задачи по тысяче раз прибавляют единицу к общей переменной `count`. В системе с нитями ОС
такой счётчик теряет прибавления: нить прерывают между чтением и записью. Пример показывает, почему
здесь этого не случается, и тем самым — главное свойство задач. Пример относится к руководству `Docu/ru/Tasks.md`.

```
MODULE ObxTasks0;
	IMPORT Tasks, Console, Strings;

	TYPE Counter = POINTER TO RECORD (Tasks.Task) END;

	VAR count: INTEGER;

	PROCEDURE (c: Counter) Run;
		VAR i, x: INTEGER;
	BEGIN
		FOR i := 1 TO 1000 DO
			x := count; count := x + 1;	(* чтение и запись без точки переключения между ними *)
			IF i MOD 10 = 0 THEN Tasks.Yield END
		END
	END Run;

	PROCEDURE Do*;
		VAR a, b: Counter; s: ARRAY 16 OF CHAR;
	BEGIN
		count := 0;
		NEW(a); NEW(b); Tasks.Start(a); Tasks.Start(b);
		WHILE Tasks.Count() > 0 DO Tasks.Step END;
		Strings.IntToString(count, s);
		Console.WriteStr("count = "); Console.WriteStr(s); Console.WriteLn
	END Do;

END ObxTasks0.
```

Модуль собирает `tools/build64.sh` (исходник — `Obx/Mod64/Tasks0.cp`; он только для amd64). В окне
BlackBox команду исполняет коммандер:

```
   ObxTasks0.Do
```

В консоли:

```sh
echo 'ObxTasks0.Do' | tools/run64.sh
```

В журнале появится:

```
count = 2000
```

## Что произошло

Команда `Do` создаёт две задачи `Counter` и запускает их: `Tasks.Start` выделяет каждой стек и
ставит её в очередь готовых. Команда исполняется вне задачи, поэтому сама крутит планировщик:
`Tasks.Step` исполняет готовые задачи, пока `Tasks.Count()` не станет нулём.

Первая задача читает `count` в `x` и записывает `x + 1`. Между чтением и записью нет точки
переключения — вызова `Yield`, `Sleep`, `Park`, `Join`, входа в занятый монитор, — и вторая задача
не может вклиниться. Каждое десятое прибавление задача зовёт `Tasks.Yield` и уходит в конец очереди;
тогда исполняется вторая задача. Задачи чередуются, но ни одно прибавление не разорвано, и итог
всегда 2000.

Если перенести `Tasks.Yield` между `x := count` и `count := x + 1`, вторая задача прочитает старое
значение, и итог станет меньше. Компилятор этого не проверяет.

В этом примере мы увидели, как описать и запустить задачу, как команда вне задачи дожидается
задач вызовами `Tasks.Step`, и почему код между двумя точками переключения неделим.
