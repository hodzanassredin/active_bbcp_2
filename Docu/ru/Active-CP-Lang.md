## 1. Введение

Active Component Pascal — это Component Pascal с двумя добавлениями: исключающей процедурой и оператором
ожидания условия. Вместе они дают монитор в том виде, в каком его ввели Хоар и Бринч Хансен и в каком он
принят в языке Active Oberon: общие данные изменяются только под защитой, а задача, которой нечего
делать, ждёт, пока условие над этими данными не станет истинным.

Язык не получил ни одного нового зарезервированного слова. Исключающая процедура помечается системным
флагом, оператор ожидания — процедура псевдомодуля `ACTIVE`. Программа, которая не импортирует `ACTIVE`,
остаётся программой на Component Pascal: её текст, её объектный код и её символьный файл не меняются.

Процессы в этом сообщении называются задачами. Задача — не конструкция языка, а объект библиотечного
модуля `Tasks`; сообщение описывает задачи лишь в той мере, в какой от них зависит смысл новых
конструкций.

Сообщение определяет язык. Оно не учебник и не описание библиотеки. Всё, что не сказано здесь, определено
«Сообщением о языке Component Pascal»; номера разделов без оговорки относятся к настоящему тексту.


## 2. Синтаксис

Синтаксис записан в расширенной форме Бэкуса — Наура, как в исходном сообщении. Изменено одно правило:

```
ProcDecl  =  PROCEDURE [SysFlag] [Receiver] IdentDef [FormalPars] MethAttributes
             [";" DeclSeq [BEGIN StatementSeq] END ident].
SysFlag   =  "[" ident "]".
```

Системный флаг — средство платформы (приложение о модуле `SYSTEM`). Настоящее сообщение
определяет одно его значение — `exclusive`.

Оператор ожидания синтаксически есть вызов процедуры:

```
ACTIVE.AWAIT(Expr)
```


## 3. Словарь

`ACTIVE` — имя псевдомодуля. Он импортируется обычным предложением `IMPORT ACTIVE`, но не существует как
файл: его единственный объект, процедура `AWAIT`, известен компилятору. В этом он подобен модулю `SYSTEM`.

`exclusive` — идентификатор системного флага. Он имеет смысл только в модуле, который импортирует
`ACTIVE`; в остальных модулях флаг с таким именем — ошибка.

Импорт `ACTIVE` служит пометкой: модуль, в тексте которого есть это слово, рассчитан на исполнение
несколькими задачами.


## 4. Задачи

Задача — последовательное исполнение программы на собственном стеке. Задачу создаёт и запускает
библиотечный модуль `Tasks`; в каждый момент исполняется одна задача.

Исполняемая задача уступает процессор другой только в *точке переключения*. Точек переключения три рода:

1. вызов процедуры, которая по своему назначению приостанавливает задачу (`Tasks.Yield`, `Tasks.Sleep`,
   приём из канала и подобные);
2. оператор ожидания, условие которого ложно (раздел 6);
3. точка уступки, если модуль компилирован с соответствующим ключом (раздел 7).

Между двумя точками переключения задача исполняется неделимо по отношению к остальным задачам. Отсюда
следует, что последовательность операторов без точек переключения не нуждается в защите.

Программа исполняется также вне задач: тело модуля, команда, обработчик события среды. Такой код ведёт
себя как задача, которая никогда не ждёт; оператор ожидания с ложным условием в нём — аварийное
завершение (раздел 8).


## 5. Исключающие процедуры

### 5.1. Объявление

Процедура, объявленная с флагом `exclusive`, называется исключающей.

```
PROCEDURE [exclusive] (b: Buffer) Put* (x: INTEGER), NEW;
PROCEDURE [exclusive] SetLevel* (x: INTEGER);
```

Исключающей может быть процедура, связанная с типом (метод), и процедура, объявленная на уровне модуля.
Процедура, объявленная внутри другой процедуры, исключающей быть не может. Флаг `exclusive` не сочетается
с другими системными флагами.

Абстрактный метод может нести флаг, но кода у него нет. У процедуры с пустым телом компилятор не ставит
вход и выход: вызов такой процедуры не входит в монитор и не ждёт его.

### 5.2. Монитор

С каждой исключающей процедурой связан *монитор* — объект, который в каждый момент принадлежит не более
чем одной задаче.

- Монитор метода — запись, обозначенная получателем. Разные записи одного типа — разные мониторы.
- Монитор процедуры уровня модуля — скрытая переменная модуля. Все исключающие процедуры одного
  модуля имеют общий монитор.

Монитором может быть любая запись; объявлять это в её типе не нужно.

### 5.3. Вход и выход

Вызов исключающей процедуры исполняется так:

1. Задача *входит* в монитор. Если монитор свободен, задача становится его владельцем. Если монитором
   владеет другая задача, вызывающая приостанавливается до тех пор, пока монитор не будет ей передан
   (раздел 6.4).
2. Исполняется тело процедуры.
3. Задача *выходит* из монитора. Это происходит при любом завершении тела: по достижении конца, по
   оператору `RETURN`, при аварийном завершении (раздел 8). Значение функции вычисляется до выхода.

Из этого следует основное свойство: тела исключающих процедур одного монитора не исполняются вперемежку.
Утверждение о данных монитора, истинное при выходе из каждой такой процедуры и не нарушаемое вне их,
истинно при входе в каждую из них. Такое утверждение называют инвариантом монитора.

### 5.4. Повторный вход

Задача, владеющая монитором, может войти в него снова: вызвать другую исключающую процедуру того же
монитора или ту же самую рекурсивно. Вход не приостанавливает её. Монитор освобождается, когда число
выходов сравняется с числом входов.

### 5.5. Вложенные мониторы

Задача может владеть несколькими мониторами. Она выходит из них в порядке, обратном порядку входа; это
обеспечено вложенностью вызовов.

Две задачи, каждая из которых владеет одним монитором и ждёт входа в другой, не продолжатся никогда. Язык
этого не предотвращает. Программа избегает тупика, входя в мониторы в одном и том же порядке.

### 5.6. Что не защищено

Флаг относится к процедуре, а не к данным. Поле записи, изменяемое помимо её исключающих процедур, монитор
не защищает. Экспорт поля для записи из модуля, где объявлен монитор, отменяет гарантию раздела 5.3.

Флаг не входит в интерфейс: вызывающему безразлично, исключающая ли процедура. Метод, переопределяющий
исключающий метод, сам исключающим не становится; ему нужен собственный флаг.


## 6. Ожидание условия

### 6.1. Форма

```
ACTIVE.AWAIT(c)
```

`c` — выражение типа `BOOLEAN`, называемое условием. Оператор допустим только в теле исключающей
процедуры — не во вложенной в неё процедуре и не в процедуре, которую она вызывает.

Аргумент ровно один. Если `c` — имя типа или процедуры, компилятор сообщает ошибку 126; если `c` не
`BOOLEAN` — ошибку 120. Вызов процедуры или присваивание в `c` — ошибка 225.

### 6.2. Смысл

Если `c` истинно, оператор не делает ничего. Если `c` ложно, задача выходит из монитора своей процедуры и
приостанавливается. Она продолжится после оператора, когда одновременно выполнено следующее: `c` истинно
и задача снова владеет монитором.

Следовательно, после оператора ожидания условие истинно. Проверять его повторно в цикле, как при
условных переменных Хоара, не нужно.

```
PROCEDURE [exclusive] (b: Buffer) Get* (OUT x: INTEGER), NEW;
BEGIN
	ACTIVE.AWAIT(b.n > 0);
	x := b.a[b.out]; b.out := (b.out + 1) MOD LEN(b.a); DEC(b.n)
END Get;
```

Ожидание — точка переключения (раздел 4). Инвариант монитора должен быть истинным перед каждым оператором
ожидания, как и перед выходом из процедуры: пока задача ждёт, монитором владеют другие.

### 6.3. Ограничения на условие

Условие вычисляет не только ждущая задача, но и та, которая выходит из монитора (раздел 6.4). Поэтому оно
подчинено двум ограничениям.

1. Условие не содержит вызовов процедур и присваиваний. Оно только читает.
2. Условие зависит лишь от того, что защищено монитором, и от локальных переменных и параметров своей
   процедуры. Компилятор проверить это не может. Условие, зависящее от посторонних данных, может стать
   истинным незаметно: ждущая задача продолжится лишь при следующем выходе какой-либо задачи из монитора.

Локальные переменные и параметры ждущей задачи доступны условию и сохраняют значения, которые имели в
момент ожидания.

`ACTIVE.AWAIT(TRUE)` — пустой оператор. `ACTIVE.AWAIT(FALSE)` приостанавливает задачу до её отмены
(раздел 8).

### 6.4. Передача монитора

Когда владелец выходит из монитора или начинает ждать, монитор передаётся так:

1. Условия ждущих задач вычисляются в порядке, в котором задачи начали ждать. Первой задаче, условие
   которой истинно, монитор передаётся; она становится готовой к исполнению.
2. Если такой задачи нет, монитор передаётся задаче, которая раньше других приостановлена при входе.
3. Если нет и такой, монитор становится свободным.

Ждущая задача с истинным условием имеет преимущество перед входящими. Между моментом, когда условие
найдено истинным, и продолжением ждущей задачи ни одна другая задача монитором не владеет, поэтому условие
не может стать ложным.

Ожидание освобождает только монитор той процедуры, в которой стоит оператор. Прочие мониторы, которыми
владеет задача, остаются за ней на всё время ожидания. Если задача входила в монитор несколько раз
(раздел 5.4), ожидание освобождает его полностью, а при продолжении число входов восстанавливается.

### 6.5. Справедливость

Язык гарантирует порядок из раздела 6.4 и ничего сверх него. Задача, условие которой становится истинным
лишь на время, пока монитором владеет другая, может ждать бесконечно.


## 7. Точки уступки

Задача, исполняющая длинный цикл без точек переключения, не даёт исполняться остальным. Модуль можно
компилировать с ключом точек уступки. Тогда в конце каждого повторения операторов `WHILE`, `REPEAT`,
`LOOP` и `FOR` стоит точка уступки, в которой задача может уступить процессор.

Правила:

1. Задача, владеющая хотя бы одним монитором, в точке уступки не переключается. Внутри исключающей
   процедуры монитор отдаётся только оператором ожидания.
2. Код, исполняемый вне задачи, в точке уступки не переключается.
3. Ключ — свойство модуля, а не его интерфейса. Вызывающему неизвестно, есть ли в вызванной процедуре
   точки уступки.

Модуль, компилированный с ключом, теряет свойство неделимости из раздела 4: между любыми двумя
повторениями цикла общие данные могут быть изменены другой задачей. Такой модуль защищает общие данные
монитором.

Модули среды исполнения компилируются без ключа: компилятор отвергает ключ у модуля каркаса.
Вызов процедуры среды из задачи неделим.


## 8. Аварийное завершение

Аварийное завершение (трап) в задаче прекращает исполнение её процедур до ближайшего места, где оно
перехвачено; если такого места нет, задача завершается. Остальные задачи продолжаются.

При аварийном завершении исключающей процедуры задача выходит из её монитора, как при обычном завершении.
Инвариант монитора при этом может быть нарушен; восстановить его — дело программы.

Аварийное завершение вызывают:

- оператор ожидания с ложным условием вне задачи;
- ошибка при вычислении условия. Если условие вычисляла выходящая задача, аварийно завершается не она, а
  ждущая, которой условие принадлежит;
- отмена задачи. Отменённая задача аварийно завершается в ближайшей точке переключения, в том числе в
  операторе ожидания.

Тупик аварийного завершения не вызывает. Задача, условие которой никто не сделает истинным, ждёт; когда
ждут все задачи, среда сообщает об этом и продолжает работу.


## 9. Ограничения реализации

1. Конструкции реализованы для процессоров x86 и AMD64. Импорт `ACTIVE` при другой цели — ошибка.
2. Все задачи исполняет одна нить операционной системы. Два оператора программы никогда не исполняются
   одновременно.
3. Модуль, код которого есть в кадре какого-либо стека, не выгружается. Поэтому модуль, монитором
   которого владеют или входа в который ждут, тоже не выгружается: вызов исключающей процедуры
   оставляет её кадр на стеке. Отдельной проверки таблицы мониторов при выгрузке нет.
4. Ключ точек уступки записывается символом `^` после имени модуля в команде компиляции.
5. Принадлежность модуля среде исполнения компилятор определяет по имени: подсистема до первой
   внутренней заглавной буквы из списка `System`, `Std`, `Text`, `Form`, `Host`, `Dev`, `Lin`,
   `Win`, либо явный список модулей подсистемы `System`. Пользовательский модуль с таким префиксом
   ключ не получит; каркасный модуль с другим именем его получит.
6. Пустое тело и абстрактный метод не берут монитор: вход и выход не генерируются. Наблюдать это
   можно только по отсутствию ожидания при занятом мониторе.
7. Импорт `ACTIVE` при другой цели даёт общую ошибку 151 (`incorrect symbol file`); отдельного
   сообщения для расширения нет.


## Приложение A. Сводка синтаксиса

```
ProcDecl  =  PROCEDURE [SysFlag] [Receiver] IdentDef [FormalPars] MethAttributes
             [";" DeclSeq [BEGIN StatementSeq] END ident].
SysFlag   =  "[" ident "]".
```

Ограничения контекста:

| Конструкция | Условие допустимости |
|---|---|
| `[exclusive]` | модуль импортирует `ACTIVE`; процедура объявлена на уровне модуля или связана с типом; нет других системных флагов; допускается числовая запись `[32]` |
| `ACTIVE.AWAIT(c)` | стоит непосредственно в теле исключающей процедуры; ровно один аргумент; `c` типа `BOOLEAN`, без вызовов и присваиваний |
| ключ точек уступки | имя модуля не принадлежит среде исполнения по правилу раздела 9, пункт 5 |


## Приложение B. Отличия от Active Oberon

| Active Oberon | Active Component Pascal |
|---|---|
| блок `BEGIN {EXCLUSIVE} … END` | процедура с флагом `[exclusive]`; исключающего блока внутри процедуры нет |
| `AWAIT(c)` | `ACTIVE.AWAIT(c)`; условие без вызовов процедур и присваиваний |
| активный объект: тело `BEGIN {ACTIVE}` | нет; задачу создаёт модуль `Tasks` |
| повторный вход в свой монитор — ошибка | разрешён |
| ошибка в исключающем блоке оставляет монитор занятым | монитор освобождается |
| разделяемый доступ `{SHARED}` | нет |
| несколько процессоров | одна нить |


## Приложение C. Пример

Ограниченный буфер — классическая задача, на которой проверяют монитор. Производитель кладёт числа,
потребитель забирает; производитель ждёт, пока буфер полон, потребитель — пока пуст.

```
MODULE ObxBuffer;
	IMPORT ACTIVE;

	CONST N = 8;

	TYPE
		Buffer* = POINTER TO RECORD
			a: ARRAY N OF INTEGER;
			in, out, n: INTEGER	(* 0 <= n <= N; n элементов начиная с out *)
		END;

	PROCEDURE [exclusive] (b: Buffer) Put* (x: INTEGER), NEW;
	BEGIN
		ACTIVE.AWAIT(b.n < N);
		b.a[b.in] := x; b.in := (b.in + 1) MOD N; INC(b.n)
	END Put;

	PROCEDURE [exclusive] (b: Buffer) Get* (OUT x: INTEGER), NEW;
	BEGIN
		ACTIVE.AWAIT(b.n > 0);
		x := b.a[b.out]; b.out := (b.out + 1) MOD N; DEC(b.n)
	END Get;

END ObxBuffer.
```

Инвариант записан в комментарии к полям. Он истинен после `NEW`, каждая процедура сохраняет его, а поля
не экспортированы; по разделу 5.3 он истинен при каждом входе. Условие каждого оператора ожидания зависит
только от полей монитора, как требует раздел 6.3.


## Приложение D. Схема реализации

Приложение не определяет язык. Оно описывает, как конструкции переведены, чтобы читатель мог оценить их
цену.

Исключающая процедура с непустым телом получает в начале вызов `Kernel.Lock(m)` и перед возвратом —
`Kernel.Unlock(m)`, где `m` — получатель или скрытая переменная модуля. Все операторы `RETURN` ведут к
одному месту выхода. У абстрактного метода и у процедуры с пустым телом этих вызовов нет.
Первый вход для данного объекта заводит запись монитора. Вход без соперников и выход берут записи
из свободных списков и памяти не выделяют; ожидание и вход в занятый монитор заводят записи
очередей.

Оператор ожидания переводится так:

```
@frm := SYSTEM.GETREG(BP);
IF ~c THEN Kernel.Await(P, @frm, m) END
```

`P` — скрытая процедура, вложенная в исключающую, с телом `RETURN c`. Ей передаётся адрес кадра ждущей
процедуры; через него условие читает её локальные переменные. Кадр существует на стеке ждущей задачи всё
время ожидания. Ядро вычисляет условие ещё раз в `Kernel.Await` через `Kernel.CallCond`, передавая кадр в
регистре `BX`. Этим объясняются оба ограничения: условие вычисляет чужая задача, поэтому в нём нет
вызовов; кадр принадлежит одной процедуре, поэтому оператор стоит в её теле, а не во вложенной.

Вызовы ядра идут через скрытую область `"$$"`; загрузчик связывает её с `Kernel`. Поэтому модуль, не
использующий расширение, не получает лишнего импорта.

Монитор — не поле записи. Среда хранит сведения о занятых мониторах в таблице по адресу записи; запись о
мониторе существует, пока им владеют или его ждут. Свободный монитор не занимает записи в таблице:
она возвращается в свободный список.

Точка уступки — вызов `Kernel.Poll`, который проверяет флаг и возвращается, если переключаться не нужно.
