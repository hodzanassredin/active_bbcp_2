# Задачи

Руководство по модулю `Tasks` для программиста на Component Pascal. Оно описывает задачу, её
состояния, интерфейс модуля, группы, планировщик и цену. Расширение языка — исключающие
процедуры, `ACTIVE.AWAIT` и точки уступки — определено в `Docu/ru/Active-CP-Lang.md`; библиотека
каналов и рабочих нитей — в `Docu/ru/Async.md`.

Задача — расширяемая запись с методом `Run` и собственным стеком. Задачи кооперативные: код
Component Pascal исполняет одна нить операционной системы, и задача уступает её только в явной
точке переключения.

## 1. Задача и точка переключения

*Задача* — последовательное исполнение программы на собственном стеке. Задачу создаёт и
запускает модуль `Tasks`; в каждый момент исполняется не более одной задачи.

*Точка переключения* — место, где исполняемая задача может уступить процессор. Точек
переключения три рода:

1. вызов операции `Tasks`, которая приостанавливает задачу: `Yield`, `Sleep`, `Join`, `Park`;
2. вход в занятый монитор и `ACTIVE.AWAIT` с ложным условием;
3. точка уступки, если модуль компилирован с ключом `^` (разделы 7 и 9.2 сообщения о языке).

Между двумя точками переключения задача исполняется неделимо по отношению к остальным задачам.
Отсюда следует, что последовательность операторов без точек переключения не нуждается в защите.

Код вне задачи — тело модуля, команда, обработчик события — ведёт себя как задача, которая
никогда не ждёт. Ожидание в нём — аварийное завершение (раздел 6).

## 2. Состояния

Состояние задачи возвращает `State(t)`; константы состояний экспортирует `Tasks`.

| Состояние | Значение | Что означает |
|---|---:|---|
| `New` | 0 | создана, но не запущена |
| `Ready` | 1 | готова к исполнению, стоит в очереди |
| `Running` | 2 | исполняется |
| `Sleeping` | 3 | спит до срока `Sleep` |
| `Waiting` | 4 | ждёт завершения другой задачи в `Join` |
| `Parked` | 5 | ждёт `Unpark` или передачи монитора |
| `Finished` | 6 | тело `Run` завершилось |
| `Cancelled` | 7 | задача отменена |

Переходы:

| Из | В | Причина |
|---|---|---|
| `New` | `Ready` | `Start` или `StartIn` |
| `Ready` | `Running` | планировщик взял задачу из очереди |
| `Running` | `Ready` | `Yield`; `Sleep` с неположительным сроком |
| `Running` | `Sleeping` | `Sleep` с положительным сроком |
| `Running` | `Waiting` | `Join`, цель ещё не завершена |
| `Running` | `Parked` | `Park`; ожидание опустошения своей группы |
| `Running` | `Finished` | тело `Run` вернулось |
| `Running` | `Cancelled` | отмена обнаружена в точке переключения или при входе в задачу |
| `Sleeping` | `Ready` | срок истёк; `Unpark`; `Cancel` |
| `Waiting` | `Ready` | цель завершена; `Unpark`; `Cancel` |
| `Parked` | `Ready` | `Unpark`; `Cancel`; монитор передан задаче |
| `Finished`, `Cancelled` | — | конечные состояния |

`Cancel` на задаче в состоянии `New`, `Ready` или `Running` состояние не меняет: он только
ставит флаг. Задача в состоянии `New` при запуске сразу переходит в `Cancelled`, и её тело не
исполняется.

## 3. Интерфейс

```
DEFINITION Tasks;

	CONST
		New = 0; Ready = 1; Running = 2; Sleeping = 3;
		Waiting = 4; Parked = 5; Finished = 6; Cancelled = 7;

	TYPE
		Task = POINTER TO ABSTRACT RECORD
			(t: Task) Run, NEW, ABSTRACT
		END;

		Group = POINTER TO RECORD END;

	PROCEDURE Cancel (t: Task);
	PROCEDURE Count (): INTEGER;
	PROCEDURE Current (): Task;
	PROCEDURE Deadlocked (): BOOLEAN;
	PROCEDURE Failed (t: Task): BOOLEAN;
	PROCEDURE GetName (t: Task; OUT s: ARRAY OF CHAR);
	PROCEDURE GroupCount (g: Group): INTEGER;
	PROCEDURE GroupFailed (g: Group): BOOLEAN;
	PROCEDURE InTask (): BOOLEAN;
	PROCEDURE Join (t: Task);
	PROCEDURE List;
	PROCEDURE ListSize (): INTEGER;
	PROCEDURE NewGroup (): Group;
	PROCEDURE NextDeadline (): LONGINT;
	PROCEDURE OwnGroup (t: Task): Group;
	PROCEDURE Park;
	PROCEDURE ResetStats;
	PROCEDURE SetName (t: Task; IN s: ARRAY OF CHAR);
	PROCEDURE SetStackSize (t: Task; size: INTEGER);
	PROCEDURE Sleep (ms: LONGINT);
	PROCEDURE Start (t: Task);
	PROCEDURE StartIn (t: Task; g: Group);
	PROCEDURE State (t: Task): INTEGER;
	PROCEDURE Step;
	PROCEDURE Switches (): LONGINT;
	PROCEDURE Unpark (t: Task);
	PROCEDURE Yield;

END Tasks.
```

Перед каждым трапом `Tasks` пишет в консоль строку `Tasks: <текст>`. Процедуры, которые
приостанавливают задачу (`Yield`, `Sleep`, `Join`, `Park`), начинают с одной и той же проверки
`CheckWait`; ниже она записана как «проверка ожидания»:

Пред: процедура вызвана из задачи — трап 20.
Пред: задача не отменена — трап 127.
Пред: не идёт обработчик действия `Services` (кроме действия планировщика) и рассылка по домену —
трап 21.

**CONST New, Ready, Running, Sleeping, Waiting, Parked, Finished, Cancelled**
Состояния задачи (раздел 2).

**TYPE Task**
ABSTRACT
Задача. Программа расширяет запись и реализует `Run`.

**PROCEDURE (t: Task) Run**
NEW, ABSTRACT
Тело задачи. Его исполняет `TaskBoot` на стеке задачи под `Kernel.Try`.

**TYPE Group**
Группа задач (раздел 4). Поля не экспортированы; состояние читают `GroupCount` и `GroupFailed`.

**PROCEDURE Start (t: Task)**
Равнозначна `StartIn(t, NIL)`.

**PROCEDURE StartIn (t: Task; g: Group)**
Выделяет задаче стек и ставит её в конец очереди готовых. При `g # NIL` записывает задачу в группу
`g`.

Пред: `t # NIL` — трап 20.
Пред: `State(t) = New` — трап 21.
Пред: стек выделен — трап 22, в консоли `no stack memory (platform does not support it)`. Стек не
выделяется, если размер больше 64 МБ или платформа не дала памяти (раздел 9).
Пост: `State(t) = Ready`; при `g # NIL` `GroupCount(g)` увеличен на 1.

**PROCEDURE Yield**
Ставит текущую задачу в конец очереди готовых и переключается на планировщик.

Пред: проверка ожидания.
Пост: задача снова исполняется; задачи, готовые раньше, исполнились до неё.

**PROCEDURE Sleep (ms: LONGINT)**
Приостанавливает задачу не меньше чем на `ms` миллисекунд. При `ms <= 0` равнозначна `Yield`.

Пред: проверка ожидания; после пробуждения проверка повторяется (отмена спящей задачи — трап 127).
Пост: срок истёк, или задачу разбудил `Unpark`; пробуждение `Unpark` потреблено.

**PROCEDURE Join (t: Task)**
Ждёт, пока `t` завершится или будет отменена. Если `t` уже завершена, возвращается сразу.

Пред: проверка ожидания (трапы 20, 127, 21); после пробуждения проверка повторяется.
Пред: `t # NIL` — трап 22.
Пред: `t # Current()` — трап 23.
Пред: `State(t) # New` — трап 24.
Пост: `State(t) IN {Finished, Cancelled}`. `Unpark` ждущей задачи ожидание не прерывает и остаётся её
следующему `Park`.

**PROCEDURE Park**
Приостанавливает задачу до `Unpark`. Пробуждение, пришедшее до вызова, не теряется: `Park`
возвращается сразу и потребляет его.

Пред: проверка ожидания; после пробуждения проверка повторяется.
Пост: пробуждение потреблено.

**PROCEDURE Unpark (t: Task)**
Запоминает пробуждение для следующего `Park` задачи `t` и будит `t`, если она спит, ждёт в `Join`,
приостановлена в `Park` или ждёт монитор. `Sleep` и `Park` потребляют пробуждение. `Join`, ожидание
монитора и `AsyncSelect.Select` его не потребляют: они ждут дальше, а пробуждение достаётся
следующему `Park`.

Пред: `t # NIL` — трап 20.
Пост: `t` готова или её следующий `Park` вернётся сразу.

**PROCEDURE Cancel (t: Task)**
Отмечает незавершённую задачу отменённой и будит её, если она спит или ждёт. Отменённая задача
трапует 127 в ближайшей точке переключения.

Пред: `t # NIL` — трап 20.
Пост: `t` отмечена отменённой; состояние `t` не меняется до её точки переключения.

**PROCEDURE NewGroup (): Group**
В задаче возвращает её собственную группу: первый вызов создаёт пустую группу с владельцем — текущей
задачей, повторный возвращает ту же. Вне задачи создаёт новую группу без владельца.

**PROCEDURE GroupCount (g: Group): INTEGER**
Число живых участников группы; `0` при `g = NIL`.

**PROCEDURE GroupFailed (g: Group): BOOLEAN**
`TRUE`, если хотя бы один участник трапнул; `FALSE` при `g = NIL`.

**PROCEDURE OwnGroup (t: Task): Group**
Собственная группа задачи `t` (`NewGroup` в `t`); `NIL`, если `t` её не создавала, и при `t = NIL`.

**PROCEDURE Step**
Исполняет готовые задачи, пока не истечёт квант 5 мс или не опустеет очередь (раздел 5).

Пред: вызов вне задачи — трап 20.
Пред: `Step` не исполняется в этот момент — трап 21.

**PROCEDURE NextDeadline (): LONGINT**
Ближайший срок спящей задачи по часам `Kernel.Time`; `-1`, если спящих нет.

**PROCEDURE Current (): Task**
Текущая задача; `NIL` вне задачи.

**PROCEDURE InTask (): BOOLEAN**
`Current() # NIL`.

**PROCEDURE State (t: Task): INTEGER**
Состояние задачи; `New` при `t = NIL`.

**PROCEDURE Failed (t: Task): BOOLEAN**
`TRUE`, если тело `t` завершилось трапом; `FALSE` при `t = NIL`.

**PROCEDURE GetName (t: Task; OUT s: ARRAY OF CHAR)**
Имя задачи; пустая строка при `t = NIL`.

**PROCEDURE SetName (t: Task; IN s: ARRAY OF CHAR)**
Задаёт имя задачи, до 63 знаков. При `t = NIL` ничего не делает. Длину `s` процедура не проверяет:
более длинное имя трапует при копировании.

**PROCEDURE SetStackSize (t: Task; size: INTEGER)**
Задаёт размер стека в байтах; `0` — 256 КБ.

Пред: `t # NIL` — трап 20.
Пред: `State(t) = New` — трап 21.
Пред: `size >= 0` — трап 22. Верхний предел здесь не проверяется; размер больше 64 МБ отвергает
`StartIn` (трап 22).

**PROCEDURE Count (): INTEGER**
Число запущенных и не убранных в `Reap` задач.

**PROCEDURE Deadlocked (): BOOLEAN**
`TRUE`, если `Step` обнаружил тупик и напечатал журнал (раздел 7).

**PROCEDURE Switches (): LONGINT**
Число переключений стека после последнего `ResetStats`.

**PROCEDURE ResetStats**
Обнуляет счётчик `Switches`.

**PROCEDURE ListSize (): INTEGER**
Длина списка всех задач. Задача, убранная в `Reap`, в список не входит.

**PROCEDURE List**
Печатает в консоль по строке на задачу: имя, состояние, границы стека, срок сна.

## 4. Группы и отмена

*Группа* хранит число живых участников (`GroupCount`), признак трапа хотя бы у одного
(`GroupFailed`) и владельца — задачу, создавшую группу. `NewGroup` запоминает текущую задачу владельцем;
вне задачи владелец — `NIL`.

Правила группы:

1. `StartIn(t, g)` регистрирует участника; `GroupCount(g)` увеличивается.
2. После возврата из `Run` владелец не завершается, пока `GroupCount(g) > 0`. Он ставит себя в
   `Parked` и ждёт, когда последний участник будет убран в `Reap`.
3. Трап участника помечает группу `failed` и отменяет остальных участников. Отмена участника
   срабатывает в его ближайшей точке переключения.
4. Отмена владельца во время ожидания группы отменяет всех участников; владелец получает
   состояние `Cancelled`.
5. Трап или отмена владельца в `Run` отменяет всех участников его группы: участники не переживают
   владельца. Владелец их завершения не ждёт; каждый завершается в своей ближайшей точке
   переключения.
6. Задача владеет одной группой: повторный `NewGroup` возвращает ту же группу (`OwnGroup`).

`Cancel(t)` отменяет одну задачу. Групповую отмену выполняет внутренняя `CancelGroup`; наружу она
не экспортируется.

## 5. Планировщик и главный цикл

Планировщик — обычное действие `Services.Action`. `Start`, `Yield`, `Sleep`, `Unpark` и передача
монитора просят его через `EnsureScheduled`: если действие ещё не зарегистрировано, оно
ставится на ближайший шаг `Services` (`Services.DoLater`). Если готовых задач нет, действие
ставится на ближайший срок спящей задачи.

`Step` исполняет готовые задачи:

1. Каждые 5 мс поднимает флаг `Kernel.RequestPoll`; точка уступки `Kernel.Poll` уступит по этому
   флагу.
2. Просматривает спящих не чаще раза на изменившееся значение `Kernel.Time` и переводит в
   готовые тех, чей срок наступил.
3. Берёт задачу из головы очереди готовых, переключается на её стек и ждёт возврата.
4. Завершённую задачу убирает в `Reap`: снимает со списка всех задач, возвращает стек в пул, будит
   ждущих в `Join`, уменьшает счётчик живых и учитывает группу.
5. Возвращает управление главному циклу, если истёк квант 5 мс или очередь опустела. Перед
   возвратом возвращает ядру стеки пула сверх 1024, не больше 16 за шаг (раздел 10).

`Step` зовут только со дна главного цикла: из действия планировщика или из теста. Вызов из задачи
и повторный вызов — трап. Задача не вытесняется по кванту: квант проверяется только после того,
как задача сама вернула управление.

Главный цикл (`System/Mod/Loop.cp`) вызывает `Services.actionHook.Step`; консольный цикл
(`Cons/Mod/Interp.cp`) вызывает его между командами и во время ожидания ввода. Поэтому задачи
исполняются и в окне, и в консоли.

## 6. Где ждать нельзя

Проверка ожидания (`CheckWait`, раздел 3) трапует в трёх случаях:

1. текущей задачи нет — `wait outside a task`, трап 20;
2. задача отменена — трап 127 («прервано»): он не совпадает с трапами предусловий, в том числе с
   трапом 21 нарушения протокола канала;
3. идёт обработчик действия (кроме действия самого планировщика) или рассылка по домену —
   `wait inside an action handler or domain broadcast`, трап 21.

Проверку проходят `Yield`, `Sleep`, `Join` и `Park`. Ожидание в мониторе вне задачи
(`Kernel.Await`) трапует 24 в модуле `Monitors` (сообщение о языке, раздел 8).

Правило: задача ждёт только в своём коде, не в обратном вызове каркаса. Код каркаса атомарен
относительно других задач; задача говорит с каркасом через действия и цикл событий.

## 7. Тупик

Когда готовых задач нет, спящих со сроком нет, а живые задачи остались, `Step` один раз печатает
журнал:

```
Tasks: deadlock: no ready tasks and no wake-up deadlines
Kernel: monitor dump
  monitor 7F...: held by "t1" count=1
    enters "t2"
  ...
```

`Tasks.Deadlocked()` сообщает это состояние тестам. Журнал — диагностика, а не аварийное
завершение: последующий `Unpark` или `Cancel` может дать прогресс. Задача, которая никогда не
уступает, не обнаруживается.

## 8. Пример

```
MODULE ObxTasks;
	IMPORT ACTIVE, Tasks, Console, Strings;

	VAR count: INTEGER; s: ARRAY 16 OF CHAR;

	TYPE Worker = POINTER TO RECORD (Tasks.Task) END;

	PROCEDURE [exclusive] Tick*;
	BEGIN INC(count) END Tick;

	PROCEDURE (w: Worker) Run;
		VAR i: INTEGER;
	BEGIN
		FOR i := 1 TO 10 DO Tick; Tasks.Yield END;
		Tick
	END Run;

	PROCEDURE Run*;
		VAR a, b: Worker;
	BEGIN
		NEW(a); NEW(b); count := 0;
		Tasks.Start(a); Tasks.Start(b);
		WHILE Tasks.Count() > 0 DO Tasks.Step END;
		Strings.IntToString(count, s);
		Console.WriteStr("ObxTasks: count="); Console.WriteStr(s); Console.WriteLn
	END Run;

END ObxTasks.
```

Две задачи вызывают исключающую процедуру модуля и уступают после каждого вызова. Команда
`Run` исполняется вне задачи, поэтому сама вызывает `Tasks.Step`, пока задачи не завершатся.
Итог — `ObxTasks: count=22`.

## 9. Цена и ограничения

**Стек.** Размер по умолчанию — 256 КБ. `SetStackSize` задаёт другой размер до запуска. Предел
задаёт ядро: `Kernel.AllocStack` отказывает при размере больше 64 МБ (`maxStackScan`). Тогда
`StartIn` трапует 22, и задача остаётся в состоянии `New`. Платформа выделяет память через `mmap` и
переводит нижнюю страницу в `PROT_NONE`: переполнение стека упирается в сторожевую страницу.
Физические страницы выделяются по касанию. Поэтому 10 тыс. задач со стеком 64 КБ занимают 640 МБ
виртуальной памяти и десятки мегабайт физической.

После завершения задачи `Reap` возвращает её стек в пул. Следующая задача того же размера берёт
стек из пула без системного вызова. Пул держит до 1024 свободных стеков; излишек планировщик
возвращает ядру (`munmap`) не больше 16 стеков за шаг.

**Цена.** Числа, условия и команды воспроизведения собраны в `docs/measurements.md`, раздел 2. При
load average 15,2–15,9 (24.11.2026), стеки 64 КБ:

| Замер | BlackBox | Go, `GOMAXPROCS=1` |
|---|---:|---:|
| создание 10 тыс. задач | 60–70 мс | 18,6–20,2 мс |
| создание 10 тыс. задач, стеки из пула | 2,3–3,1 мс | — |
| исполнение 10 тыс. задач (`Yield` и выход) | 6,9–9,3 мс | 1,8–2,5 мс |
| `Yield` двух задач | 84–113 нс | 35–60 нс |
| создание и завершение задачи, стеки из пула | 822–911 нс | 868–1 032 нс |


**Ограничения.**

1. Одна нить операционной системы, вытеснения нет. Задача уступает процессор только в точке
   переключения (раздел 1). Отмену обнаруживают процедуры с проверкой ожидания и точки уступки.
   Задача в модуле без ключа `^`, которая не вызывает приостанавливающих процедур, не прерывается.
2. Точка уступки не переключает задачу, которая владеет монитором, и код вне задачи.
3. Если платформа не выделила стек, задача не запускается, и `StartIn` трапует 22 с текстом
   `no stack memory (platform does not support it)`.
4. Рабочие нити операционной системы (`AsyncWork`) не обращаются к куче и к модулю `Tasks`;
   исключение — задания, которые сами не выделяют память. См. `Docu/ru/Async.md`.
5. Без загруженного `Tasks` ядро берёт и отдаёт свободные мониторы, но ожидание в них трапует:
   будить задачу некому.

## 10. Схема реализации

Раздел не определяет поведение; он описывает, как оно получено. Подробности —
`docs/implementation.md`, разделы 2–4.

`Tasks.Switch` — процедура `[code]`, встроенная в вызывающую. На amd64 она сохраняет 13
регистров (`rax`, `rbx`, `rbp`, `rsi`, `rdi`, `r8`–`r15`) и `rsp`, на i386 — пять (`eax`, `ebx`,
`ebp`, `esi`, `edi`) и `esp`. Синтетический адрес возврата указывает на продолжение сразу после
байтов `Switch`; для свежей задачи в слоте возврата лежит адрес `TaskBoot`. Вокруг сырого
переключения стоят `Kernel.SwitchSave` и `Kernel.SwitchRestore`: они переносят в запись стека
контекст `Kernel.Try`, `trapStack` и `tryCount`, а при возврате восстанавливают их.

`Kernel.RegisterStack` заносит стек в реестр — двусвязный список записей. `MarkLocals` сканирует
текущий стек от указателя кадра, спящие — от сохранённого указателя стека. `SwitchSave` записывает
указатель стека с запасом 256 байт на amd64 (64 на i386), чтобы сохранённые переключателем
регистры попали в скан. `Kernel.StackOf` ищет запись линейным обходом списка. Переключение его не
вызывает: задача помнит свою запись, `Step` ищет свою один раз на шаг.

`TaskBoot` — точка входа нового стека. Он вызывает `Run` под `Kernel.Try`; нормальный возврат
даёт `Finished`, трап — `Failed(t)` и `Finished`, отмена — `Cancelled`. После тела `TaskBoot` ждёт
опустошения своей группы. Затем `Finish` переключается на главный стек, где `Step` убирает
задачу в `Reap`.

Планировщик хранит готовые задачи в FIFO-очереди, спящие — в четверичной куче по сроку: вершина
кучи — ближайший срок. Пул свободных стеков — односвязный список, связанный через верхние слова
самих стеков (`TakeStack`, `GiveStack`); `TrimPool` возвращает ядру излишек сверх `poolMax` = 1024
порциями до `trimStep` = 16 стеков за шаг. `Reap` снимает задачу из двусвязного списка всех задач
за O(1): иначе завершённые задачи удерживали бы свои объекты до конца процесса. `CLOSE` модуля
снимает планировщик (`Kernel.SetScheduler(NIL)`), убирает действие из `Services` и возвращает ядру
стеки живых задач и пула.
