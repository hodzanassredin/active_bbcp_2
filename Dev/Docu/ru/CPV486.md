# DevCPV486: размещение данных и обход AST для i386

[Исходник](../../Mod/CPV486.cp) · [Архитектура](Compiler-Architecture.md) · [CPC486](CPC486.md) · [CPE](CPE.md)

DevCompiler импортирует модуль под алиасом DevCPV. Здесь две разные стадии: Allocate дополняет таблицы размещением, Module генерирует код по AST. Между ними драйвер вызывает CPT.Export.

## Размещение

`Init(opt)` инициализирует CPL/CPC, флаг ASSERT и служебные объекты COM. `TypeSize` вычисляет размеры/выравнивание, в том числе по callback из CPB. `TypeAlloc` защищён allocated от повторной рекурсии, обрабатывает базовые типы, поля и методы, создаёт необходимые якоря descriptor через CPE.

| Процедура | Результат |
|---|---|
| TypeSize / GTypeSize | size, align, смещения полей и сведения о массивах |
| EnumTProcs | Нумерация методов interface-record в порядке объявления через strobj.link/nlink |
| CountTProcs | Обработка методов обычной записи и наследования |
| Parameters | Смещения параметров и начальные размеры/флаги процедур |
| Variables | Смещения переменных; регистры здесь ещё не назначаются |
| Procedure / TProcedures / Objects | Рекурсивный обход объявлений и вложенных областей |
| Allocate | Глобальные переменные из topScope.scope, объекты из topScope.right; dsize в CPE |

Variables уменьшает накопленный offset и выравнивает его; отрицательный obj.adr здесь закономерен. Глобальный размер сохраняется как `DevCPE.dsize := -gvarSize`. Окончательное значение адреса требует контекста сегмента/кадра.

## Генерация

Module сначала вызывает CPH.UseReals, затем CPM.NewObj и CPE.OutHeader. Генерируются тело модуля, CLOSE, служебные COM-процедуры, процедуры из prog.left, поддержка stack allocation, затем CPE.OutCode. При ошибке временный object file закрывается через DeleteObj.

`design` переводит обозначение в CPL.Item; `expr` вычисляет выражение; `condition` строит ветвление; `stat` обходит последовательность операторов, `procs` — процедуры. DualExp и Check помогают выбрать порядок/регистровые ограничения. Списки проходят через Node.link.

Для CASE используются IfStat/CaseStat/CasePart и механизмы таблиц/деревьев переходов. Для строк — StringOp/StringCopy/AddCopy. Для COM — HandleIPtrs, IPAssign, InitializeIPVars, ReleaseIPVars и генерация QueryInterface. Такие операции могут порождать существенно больше кода, чем один вызов CPL.

## Контракты с соседями

- Frontend должен построить корректные классы узлов и типы; backend продолжает проверять ограничения реализации и необходимые runtime checks.
- Перед Export уже известны размеры и номера методов; до Allocate отпечатки размещения вычислять рано.
- CPC получает Item и ограничения hint/stop; CPL знает точную форму инструкции.
- CPE собирает код/данные/links и метаданные; CPV сообщает позиции и reference-информацию.

При изменении размещения проверять параметры VAR-record (адрес плюс сведения о типе), динамические массивы, наследование и вложенные процедуры. При изменении обхода — порядок побочных эффектов, ветвления, CLOSE и освобождение interface pointers.
