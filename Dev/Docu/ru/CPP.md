# DevCPP: грамматика и построение модуля

## Контракт

Единственная экспортируемая процедура `Module(VAR prog)` разбирает модуль и возвращает корень Nenter. Перед вызовом DevCompiler готовит CPM, CPT и callback размера CPB. Парсер использует один текущий токен и глобальное состояние CPS; при ошибках продолжает разбор в пределах предусмотренного восстановления, а допустимость запуска backend определяет CPM.noerr.

Module читает MODULE/имя, вызывает CPT.Open, обрабатывает IMPORT с алиасами через CPT.Import, затем Block и CPB.Enter. `prog.left` содержит процедуры, `prog.right` — тело, `prog.link` — секцию CLOSE при её наличии. Позиции начала/конца сохраняются в conval. В конце проверяются имя после END и точка.

## Порядок чтения процедур

| Группа | Основные процедуры |
|---|---|
| Имена и экспорт | qualident, CheckMark, CheckSysFlag |
| Типы | Type, RecordType, ArrayType, PointerType |
| Объявления | Block, ProcedureDeclaration, FormalParameters, Receiver |
| Выражения | Expression → SimpleExpression → Term → Factor; selector, Sets |
| Вызовы | ActualParameters, StandProcCall |
| Операторы | StatSeq, CaseLabelList |
| Незавершённые объявления | SetType, FixType, CheckForwardTypes, CheckRecords, CheckUnimpl |

Парсер определяет, какая конструкция встретилась, а CPB проверяет совместимость операндов и строит нормализованный узел. Но разделение не абсолютно: CPP проверяет области, экспорт, атрибуты, наследование и завершённость типов.

## Области и цепочки

CPT.Insert включает объект в дерево имён. CPP отдельно связывает параметры и переменные через link, сохраняет первую переменную в Head.scope, открывает/закрывает области процедур. Поля записи имеют и дерево имён, и последовательность; методы дополнительно имеют цепочку nlink для порядка объявления.

SetType сохраняет неразрешённую ссылку в userList, если имя объявлено позже. FixType/CheckForwardTypes связывают её с действительным типом; CheckRecursiveType проверяет недопустимую рекурсию значений. Разрешённый цикл через указатель принципиально отличается от бесконечного вложения RECORD по значению.

Для именованного указателя на безымянный RECORD в Block может быть создано синтетическое объявление `PointerName^`. Это существенно для strobj, сериализации и отпечатков CPT.

## Нормализация конструкций

FOR не имеет собственного Nfor: StatSeq строит начальное присваивание, при необходимости временную `@for` для однократного вычисления верхней границы, Nwhile и приращение счётчика. Направление сравнения зависит от знака BY.

WITH временно меняет `Object.typ`, сохраняя исходный в ptyp и восстанавливая его после ветви. Узлы guard передают уточнённый тип backend. Ошибка восстановления здесь повлияет на следующие операторы при корректной таблице объявлений.

CASE собирает диапазоны меток, проверяет пересечения и передаёт конструкцию в CPB.OptimizeCase. Для строк и параметров могут добавляться предварительные операторы/временные переменные через CPB.CheckBuffering и CheckVarParBuffering: нельзя считать, что один оператор исходника всегда равен одному узлу AST.

## Связь с раздельной компиляцией

CheckAlloc выставляет typ.pvused; расширение RECORD также зависит от внутреннего устройства базы. qualident вызывает FindImport, отмечающий used. Эти флаги затем определяют проверки в CPE.OutImport. Отбрасывать их как «не относящиеся к парсингу» нельзя.

Изменения грамматики сверять с DevAnalyzer: он содержит собственный расширенный разбор, а не вызывает DevCPP.Module. Для API команд и выбора исходника см. DevCompiler.
