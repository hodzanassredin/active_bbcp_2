# DevCPE: буфер кода и объектный файл

[Исходник](../Mod/CPE.cp) · [Архитектура](Compiler-Architecture.md) · [Отпечатки CPT](CPT.md)

Модуль связывает backend с форматом `.ocf`: хранит генерируемые байты, константы, ссылки, имена и descriptor, затем пишет их через CPM. Это другое назначение, чем экспорт `.osf` в CPT.

## Память генератора

`GenByte/GenShort/GenWord` добавляют код и двигают pc. `Put*` исправляют уже записанное; `This*` читают буфер. Код хранится блоками. `dsize` — объём переменных, назначенный CPV.Allocate; он не равен длине метаданных или кода.

AllocConst группирует/распределяет константы; GetLongWords/GetRealWord/GetRealWords переводят значения в машинные слова. AllocTypDesc при необходимости создаёт анонимный объект-якорь типа. Само окончательное описание типа готовится и записывается позже через PrepDesc/OutDesc.

OffsetLink и Object.links связывают места, где нужен адрес объекта с определённым смещением. Не путать эти цепочки с Object.link для параметров/полей и Node.link для операторов.

## Жизненный цикл файла

CPV.Module вызывает CPM.NewObj, CPE.OutHeader, пишет reference-информацию при генерации, затем CPE.OutCode. Init получает processor и опции, Close снимает удерживаемые структуры.

OutHeader пишет processor и временные поля размеров, собирает импорты (включая DLL с префиксом `$`), имя модуля и выравнивает заголовок. OutCode завершает reference-блок и формирует остальные части:

1. Экспортируемые объекты и сигнатуры (константа outSignatures сейчас TRUE).
2. Карту глобальных указателей, подготовку type descriptors.
3. Таблицу импортов, имена, константы с выравниванием.
4. Module descriptor, таблицу процедур и type descriptors.
5. Машинный код.
6. Цепочки исправлений локальных и внешних адресов, включая NewRec/NewArr.
7. Список использованных импортных объектов.
8. Исправление размеров/смещений заголовка и RegisterObj при noerr/outObj.

Это порядок текущего OutCode, а не полная бинарная спецификация. Точные размеры записей читать совместно с DevLnkLoad и системным загрузчиком. Изменение writer без синхронного изменения reader несовместимо с существующими файлами.

## Object Model на границе файла

OutExport пишет метаданные экспортов. Для типов готовятся публичный и приватный fingerprints структуры. OutImport обходит импортную область и выбирает только необходимые объекты/типы по used, pbused, pvused и links.

Для составного типа при pvused или анонимном имени записывается pvfp, иначе pbfp. Биты opt различают требование видимого имени и приватной структуры. Если нужен приватный отпечаток объекта с history=inconsistent, вызывается CPT.FPrintErr(249). Остальные объекты используют FPrintObj.

Так замыкается контракт CPT: разрыв рекурсии при вычислении fingerprints компенсируется явной записью дополнительных зависимостей. Нельзя упростить OutImport до списка имён из исходного IMPORT: он не содержит сведений о том, какая часть интерфейса использована.

## Runtime и отладчик

FindPtrs ищет указатели в глобальных значениях; OutDesc/OutModDesc записывают сведения для выполнения программы. OutRefs/OutSourceRef и OutRefName обслуживают отладочную информацию. Изменение размещения RECORD затрагивает одновременно offsets, pointer maps, descriptors и fingerprints.
