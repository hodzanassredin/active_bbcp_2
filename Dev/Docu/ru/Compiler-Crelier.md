# Книга Крелиера и реализация Dev

Источник: Régis Bernard Joseph Crelier, *Separate Compilation and Module Extension*, ETH dissertation No. 10650, 1994, [локальный PDF](../../Sciences_Crelier_1994.pdf).
Здесь важны две темы: архитектура OP2 и проверка совместимости независимо компилируемых модулей. Книга не является спецификацией текущего Component Pascal или бинарных файлов bbcb2.

## Главные идеи для DevCPT

### Граф не равен дереву

Область видимости — дерево поиска имён. Типы — граф с разделяемыми узлами и циклами. Узлы AST ссылаются на объявления и типы. Именно поэтому тип сериализуется один раз с номером, а последующие вхождения становятся ссылками.

### Совместимость проверяется по использованию

Добавление нового экспортируемого имени не должно автоматически менять контракт всех старых имён. Клиент хранит сведения о реально нужных объектах. Смена адреса процедуры разрешается линкером, а смена её сигнатуры требует проверки совместимости.

### Циклы разрываются с учётом семантики

Для передачи указателя обычно достаточно идентичности его типа и цепочки расширения базы. Для разыменования уже нужна структура базы. Поэтому отпечаток именованного указателя на именованный тип не разворачивает всю базу, а разыменование отдельно отмечает её использование. Просто запретить рекурсию флагом без этого второго шага было бы недостаточно.

### Приватная структура тоже бывает частью контракта

Клиент, выделяющий переменную RECORD, знает её размер. Клиент, читающий публичное поле через указатель, может не знать полного размера. pbfp и pvfp отражают это различие. Скрытые указатели должны сохраняться в описании для работы со структурой памяти, хотя исходные имена скрыты.

### Старый файл нужен для сообщения об изменениях

Object Model не основывает совместимость на истории слоёв. Старый `.osf` позволяет сравнить интерфейс и сообщить о его изменении; сами отпечатки вычисляются из атрибутов текущего графа. Поэтому `history` в Object — временный результат сравнения, а не постоянный журнал поколений.

## Отличия, которые нельзя потерять

| Книга / историческая реализация | Текущий исходник |
|---|---|
| XOR с циклическим сдвигом в OPM.FPrint, с. 107 | CRC32 в DevCPM.FPrint; старая формула закомментирована |
| Начальные ссылки типов 0–15 | FirstRef=32, совместимость чтения версии 0 через FirstRef0=16 |
| Теги файлов OP2 в приложении | SFtag/OFtag DevCPM, processor, actVersion=1 и расширенный набор тегов |
| Имена в фиксированных массивах | Object.name — динамическая String; общая пустая строка null; Name имеет предел 256 |
| Исходные формы Oberon-2 | CHAR/SHORTCHAR, LONGINT, COM, ANYREC/ANYPTR, атрибуты процедур/записей, специальные sysflag |
| Разрешение изменений опциями `\s`/`\e`, с. 123 | FPrintErr для 250–253 печатает сообщения и меняет флаги; 249 остаётся ошибкой |
| pvfp в конце смешивается с pbfp | Публичные атрибуты полей/методов прямо включаются в обе свёртки; прежняя финальная строка закомментирована |
| Описание анонимной записи за именованным указателем | CPP может создавать каноническое синтетическое имя `PointerName^` |
| Историческое размещение/формат OPL | Отдельный CPE и несколько современных для этой кодовой базы путей ELF/PE/boot image |

При расхождении текста книги и листинга следует проверять алгоритм в текущем исходнике. Например, проза на с. 111 говорит о публичном отпечатке элемента массива, но приведённый на с. 109 алгоритм и текущий FPrintStr используют `BaseTyp.pvfp`.

## Что этот разбор не устанавливает

Он объясняет механизмы по исходникам. Он не доказывает отсутствие коллизий 32-битных отпечатков, не подтверждает полную эквивалентность всех вариантов линкера и не переносит результаты измерений OP2 1994 года на bbcb2. Изменения формата или свёртки требуют согласования с читателями файлов и отдельной проверки старых клиентов.
