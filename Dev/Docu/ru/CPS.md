# DevCPS: лексический анализатор

[Исходник](../Mod/CPS.cp) · [Архитектура](Compiler-Architecture.md) · [Парсер](CPP.md)

## Вход и результат

`Init` устанавливает текущий символ `ch` в пробел. `Get(VAR sym)` читает следующий токен через DevCPM.Get. Вид возвращается в sym, дополнительные данные — в глобальных `name`, `str`, `lstr`, `numtyp`, `intval`, `realval`. Поэтому их надо использовать до следующего Get; это не независимый объект Token.

| Результат | Дополнительные поля |
|---|---|
| ident | name: DevCPT.Name, ограниченный UTF-8 буфер имени |
| number | numtyp и intval/realval |
| string | str; при длинных символах lstr; intval — длина с завершающим 0X |
| Ключевое слово / пунктуация | Числовой код sym |
| eof | Достигнут DevCPM.Eot |

numtyp: 1 char, 2 integer, 4 real, 5 int64, 6 real32, 7 real64. Нельзя путать эти значения с кодами форм Struct. Для LONGINT значение впоследствии передаётся в CPB как пара intval/realval.

## Разбор

- `Identifier` распознаёт имя, преобразует его для внутреннего хранения и проверяет ключевое слово. Есть расширяемый callback `checkKeyword` и `StdKeywords`.
- `Number` разбирает числовой литерал, основание, экспоненту/суффиксы и диапазон. Полный набор допустимых форм сверять с кодом и [описанием языка](../../../Docu/CP-Lang.md).
- `Str` читает кавычки двух видов. Литерал из одного символа возвращается как number/char. Для более длинного текста выбираются SHORTCHAR либо CHAR buffers. Внутренний UTF-8 для длинной константы создаёт уже CPB.NewString.
- Вложенная `Comment` обрабатывает вложенные `(* ... *)`. EOF внутри незакрытого комментария даёт ошибку 5.
- Get пропускает пробельные/управляющие символы и NBSP, распознаёт составные `:=`, `<=`, `>=`, `..`; обновляет позиции в CPM.

Числовые значения операторов согласованы с CPB/CPP и backend. Изменение enum в одном месте может изменить смысл узла на другой стадии. При расширении лексики проверить и наборы/диапазоны кодов в парсере.

## Проверка изменений

Проверять границы числовых типов, экспоненты, одиночный символ против строки, длинную Unicode-строку, вложенные комментарии, EOF и положение маркера после комментария. DevReferences и DevAnalyzer также используют CPS: изменение scanner влияет не только на компиляцию.
