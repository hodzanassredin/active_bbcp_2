# DevBootLinker: образ с готовым загрузчиком

[Исходник](../../Mod/BootLinker.cp) · [Архитектура](Compiler-Architecture.md)

Модуль упаковывает существующие `.ocf` после готового boot loader. В отличие от [Linker1](Linker1.md), здесь не строится обычный ELF из отдельных секций кода и данных. Заголовочный комментарий исходника содержит описание boot image.

## Интерфейс и порядок

`Link` читает параметры из DevCommanders.par: имя результата, `:=`, список модулей с обозначением kernel/main. BuildModList собирает список, ValidateModList проверяет его, WriteExe копирует загрузчик и объектные файлы. Импорты должны предшествовать импортирующим модулям.

`SetLoaderName(name)` меняет путь к загрузчику; по умолчанию это `Dev/Rsrc/exe.img`. Для поиска Code используется Librarian. Ошибки отсутствующего loader, kernel/main и пустого списка выводятся в Log/статус.

## Формат

`Executable = BootLoader + Header + {ObjFile}`. Header содержит fileTag, version, число модулей, имена kernel/main, отпечатки NewRec/NewArr. Write4 задаёт little-endian порядок. ObjFile копируются целиком.

Проверять константы по процедурам записи: текстовая последовательность байтов fileTag в старом комментарии не заменяет фактическое Write4. Константы NewRecFP/NewArrFP здесь отличаются от DevLnkLoad; это признак отдельного исторического контракта, а не доказанная взаимозаменяемость путей.

MakeExecutable в текущем исходнике имеет закомментированное тело chmod. Поэтому успешная запись не означает, что этот модуль установил исполняемый бит. Совместимость имеющегося exe.img с текущим Kernel требует отдельной проверки; документация не утверждает, что этот путь запускался.
