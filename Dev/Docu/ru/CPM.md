# DevCPM: среда компилятора и параметры машины

[Исходник](../../Mod/CPM.cp) · [Архитектура](Compiler-Architecture.md) · [DevCPT](CPT.md)

## Назначение и состояние

Модуль изолирует чтение TextModels, диагностику, запись `.osf`/`.ocf` и параметры целевого представления. Его импортируют почти все стадии. `Init(source,logtext_)` подключает Reader, удаляет прежние маркеры, сбрасывает `noerr`, `options`, позиции и число ошибок. Параметр logtext_ в текущем теле Init не используется. `Close` снимает ссылки на файлы и readers.

Целевые константы здесь конкретны: PointerSize=4, ProcSize=4, DArrSizeA=8, DArrSizeB=4; размер дескриптора динамического массива вычисляется с учётом `typ.n`. MaxStruct=16000 ограничивает таблицы CPT, MaxExts=15 связан с runtime type descriptor. Изменение этих чисел затрагивает backend, сериализацию и runtime, а не только frontend.

## Ввод и ошибки

`Get` читает CHAR и пропускает встроенные viewcode. Файловое преобразование исходника в TextModels происходит выше, через DevCompiler/Converters/Librarian. `curpos`, `startpos`, `errpos` различают текущую позицию, начало токена и позицию диагностики. CPS поддерживает их при сканировании.

`err(n)` передаёт текущую позицию в `Mark(n,pos)`. Mark ведёт список диагностик, учитывает повторные позиции и меняет состояние ошибки; `InsertMarks` вставляет DevMarkers в текст. Для понимания сообщения смотреть также ресурсы Dev и [платформенную документацию](Platform-Specific.md), а не только числовой код в CPB/CPP.

`options` здесь содержит языковые/системные признаки (COM, SYSTEM, Oberon и т. п.). Набор `opt`, передаваемый DevCompiler в backend, содержит опции генерации. Их одинаковые номера битов не означают одинаковый смысл.

## Файлы

| Семейство | Контракт |
|---|---|
| OldSym / CloseOldSym | Найти файл через Librarian категории Sym, проверить SFtag; `@file` читает заранее заданный `file` |
| SymR* / SymW* | Компактные целые, строки по байтам, множества, вещественные; обновление checksum |
| NewSym / RegisterNewSym / DeleteNewSym | Создать временный файл, зарегистрировать по имени или закрыть его |
| SymReset | Поставить writer на смещение 4, чтобы CPT исправил processor после тега |
| NewObj / ObjW* / ObjSet / ObjLen | Запись объектного файла, позиционирование и исправление заголовка |
| RegisterObj / DeleteObj | Завершить выпуск либо закрыть временный объектный файл |

SFtag=`6F4F5346H`, OFtag=`6F4F4346H`. Имена и пути определяет Librarian; не следует дублировать его правила в CPT. `ask` управляет созданием каталогов при выпуске файлов.

## Отпечаток и checksum

`FPrint` смешивает INTEGER с текущим fp через таблицу CRC32, по четырём байтам. FPrintSet/Real/LReal приводят значения к требуемым словам; LoWord/HiWord учитывают порядок байтов host. `ChkSum` обновляет контрольную сумму байтов потока `.osf`.

Это разные уровни: CPT выбирает семантические атрибуты для отпечатка, а checksum характеризует записанный поток. В книге Крелиера использована другая функция смешивания; старая формула в этом исходнике закомментирована. Менять FPrint без согласования с готовыми объектными файлами и проверяющими их модулями нельзя.

## Системные признаки

Get*SysFlag и Propagate*SysFlag проверяют представления записей, указателей, массивов, процедур и параметров. PutUtf8/GetUtf8 обслуживают внутреннее хранение длинных строк. При ошибке специальных типов проверять именно эту интерпретацию sysflag вместе с CPB и backend.
