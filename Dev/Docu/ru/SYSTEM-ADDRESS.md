# SYSTEM.ADDRESS

SYSTEM.ADDRESS — целочисленный тип размером с указатель, предоставляемый этой
версией компилятора Dev. Он доступен после `IMPORT SYSTEM` и предназначен для
адресов памяти, смещений в байтах и значений native API размером с указатель.
Это расширение стандартного языка Component Pascal.

| Целевая платформа | Размер | Целочисленное представление |
|---|---:|---|
| i386 | 4 байта | INTEGER, знаковое 32-битное число |
| AMD64 | 8 байт | LONGINT, знаковое 64-битное число |

Размер определяется целевой платформой компиляции, а не архитектурой процесса
компилятора. INTEGER на обеих платформах остаётся 32-битным, LONGINT — 64-битным.
SYSTEM.ADDRESS не является беззнаковым типом и не запрещает арифметику или
сравнения адресов. Для него действуют обычные правила совместимости целых
чисел при присваивании и передаче параметров.

## Доступ к памяти

SYSTEM.ADR возвращает SYSTEM.ADDRESS. Первый аргумент GET и PUT, а также адреса
источника и назначения MOVE можно передавать непосредственно:

```componentpascal
	IMPORT SYSTEM;

	VAR address: SYSTEM.ADDRESS; value: INTEGER;

	PROCEDURE Example;
	BEGIN
		value := 42;
		address := SYSTEM.ADR(value);
		SYSTEM.GET(address, value);
		SYSTEM.PUT(address, value)
	END Example;
```

Размер чтения GET или записи PUT определяется типом аргумента со значением.
В примере он равен четырём байтам на обеих платформах. Если значение имеет тип
SYSTEM.ADDRESS, размер равен четырём или восьми байтам соответственно. MOVE
копирует указанное количество байт; смещения при арифметике адресов также
задаются в байтах.

Преобразовывать адрес в ANYPTR только для передачи в GET, PUT или MOVE не
требуется. Для получения числового адреса из указателя применяется
`SYSTEM.VAL(SYSTEM.ADDRESS, pointer)`. Обратное преобразование требует
подходящего указательного типа; оно не выделяет память и не проверяет адрес.

## Native API и хранение данных

SYSTEM.ADDRESS следует использовать для параметров и результатов API размером
с указатель, например native-указателей и дескрипторов. Поля фиксированной
разрядности должны сохранять размер, заданный ABI: Windows DWORD, BOOL и LONG
остаются INTEGER и в Windows AMD64. Сам тип SYSTEM.ADDRESS не обеспечивает
совместимость записи с C: выравнивание и промежутки между полями также должны
соответствовать ABI.

Адрес является целым числом, а не управляемым указателем. Нельзя полагаться на
переменную с адресом для удержания объекта от сборки мусора: следует сохранять
ссылку подходящего указательного типа. Адреса AMD64 нельзя сужать до INTEGER.
Размер записей с полями SYSTEM.ADDRESS может различаться между платформами;
такие записи не подходят для платформонезависимого формата файла или сети.

Реализация: DevCPT.InitBasic создаёт тип нужной разрядности; DevCPB назначает его
результату SYSTEM.ADR и проверяет адресные аргументы операций с памятью.
