# DevCPB: семантика и построение AST

[Исходник](../Mod/CPB.cp) · [Архитектура](Compiler-Architecture.md) · [Устройство Node](CPT.md)

## Контракт

CPB получает уже распознанные конструкции от CPP, проверяет типы/допустимость операций, сворачивает константы и создаёт или заменяет DevCPT.Node. Большинство функций принимают `VAR x`: после вызова корень может быть другим узлом. Это важно при сохранении ссылок на прежний x.

Модуль импортирует CPT и CPM. Машинный расчёт размера доступен через `typSize`, который DevCompiler связывает с CPV486.TypeSize; прямого IMPORT backend нет.

## Основные семейства

| Процедуры | Назначение |
|---|---|
| NewLeaf | Объект объявления → Nvar/Nvarpar/Nconst/Ntype/Nproc; установка readonly |
| Construct, Link | Составной узел и последовательность по link |
| NewIntConst, NewLargeIntConst, NewRealConst, NewString | Типизированные константы |
| DeRef, Index, Field, TypTest | Обозначения, выбор поля/элемента, проверки типа |
| MOp, Op, In, SetRange, SetElem | Операции, приведение операндов, свёртка констант |
| CheckAssign, Assign | Совместимость, преобразование правой части, разрешённость записи |
| PrepCall, Param, Call, CheckParameters | Процедурные вызовы и формальные/фактические параметры |
| StPar0, StPar1, StParN, StFct | Встроенные процедуры; собственные правила числа и типов аргументов |
| Enter, Return, Inittd | Тело процедуры/модуля, возврат, инициализация descriptor |
| GetTempVar, CheckBuffering, CheckVarParBuffering | Временные значения и сохранение семантики строковых выражений |
| OptimizeCase | Выбор представления ветвления по диапазонам |

## Что делает результат пригодным для backend

1. У выражений задан typ; неявные преобразования представлены нужными узлами/константами.
2. Вызов хранит обозначение процедуры слева, цепочку фактических параметров справа и формальные параметры в obj.
3. Присваивание содержит допустимое изменяемое назначение; IN-параметры и read-only экспорты запрещают запись.
4. Константные операции проверены на допустимость/диапазон до генерации кода.
5. Семантические зависимости от импортных структур отмечены used/pbused/pvused.

NewLeaf копирует запись Const для именованной константы, но не копирует сам строковый массив ext. Служебные преобразования не должны разрушать общую строку. NewString хранит String16 в ext как UTF-8, длину в символах с нулём — в intval2, признак отсутствия адреса — в intval.

LONGINT-константы имеют составное внутреннее представление через realval и intval. Читать их как один intval ошибочно; соответствующие AddConst/MulConst и GetLongWords в CPE содержат правила обработки.

## Побочные эффекты, которые легко пропустить

- DeRef именованного указателя на именованную базу устанавливает BaseTyp.pbused: это дополнение к разрыву циклов fingerprinting.
- CheckAssign для структурных значений устанавливает pvused; размер копии является частью зависимости.
- StaticLink отмечает необходимость доступа к внешнему кадру; leaf и процедурные флаги используются backend.
- GetTempVar добавляет объявление в таблицу: преобразование AST может менять и перечень локальных переменных.
- OptIf и свёртки могут убирать/заменять узлы, поэтому положение в исходнике и link следует сохранять согласно вызывающему коду.

При изменении операции проверять отдельно константную и неконстантную ветви, mixed types, readonly, побочные эффекты аргументов и порядок вычисления. Один успешный пример сложения целых не проверяет семантический контракт Op.
