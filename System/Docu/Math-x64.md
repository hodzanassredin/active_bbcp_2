# Math on AMD64

`System/Mod64/Math.cp` exports the same 35 procedures as `Math.cp`.
The x64 source filter selects it when compiling `Math`. The public interface and
module name remain `Math`; both Windows and Linux use this implementation.

## Audit and changes

All exported procedures were inspected, including the private x87 instructions
they use. The remaining inline instructions operate on x87 registers and contain
no pointers or hard-coded local-variable offsets. Binary64 sign/exponent access
uses little-endian words, valid on both supported x86 platforms.

- `Exponent` keeps the stack-independent IEEE 754 implementation introduced by
  the decimal-formatting fix. The old i386 frame displacement must not return.
- `IntPower` previously pushed two x87 values before handling `MIN(INTEGER)`.
  The recursive branch leaked both values and repeated calls trapped with 143.
  Exponentiation now uses local REAL values and checks the recursive case before
  any computation. The `n = 0` path returns 1 without computing a reciprocal.
- `ArcCosh` previously lost relative precision for the next binary64 number above
  1. The small-argument branch now uses
  `log1p(t + sqrt(t*(t+2)))`, where `t = x-1`, with x87 FYL2XP1.
- The optional `IsNaN` guards in numerical functions are commented out to avoid
  their per-call overhead. NaN inputs are excluded from the regression vectors;
  no NaN-propagation guarantee is made for those functions. The public IsNaN
  procedure and the Mantissa/Exponent/Real encoding remain available.

The i386 implementation is retained in `Math.cp`.

## Tests

Run from the project root:

```sh
python3 System/Test/check_math64.py
```

The Linux test reuses `build/blackbox-lin64` and runs in console mode. It never
opens GUI windows or synthesizes mouse input. The Windows test builds an isolated
PE in `build/math64-windows` and executes it with Wine. Select one platform with
`--platform windows` or `--platform linux`; override paths with `--windows-dir`
and `--linux-dir`. Build and execution logs are saved in those directories.

`CheckMath64.Run` contains 7,482 checks:

| Procedures | Coverage |
| --- | --- |
| Pi, Eps | Independent binary64 constants |
| Sqrt, Exp, Ln, Log | Known values, logarithm/exponential ranges, subnormal/large inputs |
| Power, IntPower | Positive/negative/zero exponents, infinity, underflow/overflow, MIN(INTEGER), repeated calls |
| Sin, Cos, Tan, SinCos | Signs, zeros, quadrants, random values, output order, large finite arguments |
| ArcSin, ArcCos, ArcTan, ArcTan2 | Endpoints, quadrants, signed zeros, infinite arguments |
| Sinh, Cosh, Tanh, ArcSinh, ArcCosh, ArcTanh | Small/large values, near-domain boundaries, infinity |
| Floor, Ceiling, Round, Trunc, Frac, Mod1 | Positive/negative/tie values, random fractions, large integers |
| Sign, SignBit, CopySign, IsNaN | Signed zeros, finite/infinite values, non-NaN classification |
| Mantissa, Exponent, Real | All power-of-two exponents from -1074 to 1023, negative reconstruction, special values |

The suite also runs `CheckRealFormat64.Run`, including the Document Size
formatting regression. The runner verifies identical exported signatures and
coverage of every exported procedure.

The deterministic vectors in `Check/Mod/Math64.cp` are generated by
`System/Test/generate_math64.py` using Python's binary64 math library as an
independent reference. Most comparisons use relative tolerance 3e-14; zero is
checked exactly. Sine/cosine allow an absolute 1e-16 near zeros. The retained x87
trigonometric reduction has limited accuracy for large arguments: the 1e10 cases
allow absolute error 2e-11. This inherited limitation is not a guarantee of full
binary64 accuracy for arbitrary huge angles. Invalid inputs outside documented
preconditions are not accepted by these tests.

The final suite passes on Windows x64 under Wine and Linux x64, with no traps.
